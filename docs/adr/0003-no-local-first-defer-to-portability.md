# 存储层不搬到本地；「本地优先」降级为可迁移性

概念书把「本地优先 / 绝对隐私 / Ollama 离线模型」列为四大卖点，而代码实际是云 Postgres（Neon）+ Netlify 部署。这不是疏忽——项目原本写本地 `data/*.json`，2026-10-11 为能部署（Netlify 的函数文件系统只读，写本地文件必然失败）才整体切到云端数据库。**在纯 Web 架构里，「发一个网址给评委打开」与「数据留在用户本机」是互斥的。**

**决定**：不把存储层搬回本地，也不做桌面客户端壳。「数据是你的」这条承诺改由**可迁移性**兑现——知识库可一键导出为 OKF bundle（纯 markdown + YAML frontmatter），随时能被任何读 markdown 的工具带走。

**为什么**：换存储层等于重做整条存储与部署链路，且会丢掉已经跑通的部署链路和回归测试这套最大的工程资产；而对用户可见的「数据所有权」，大部分可以由「可完整导出、不锁定」兑现。

**后果**：**不得**在任何对外材料（PPT / 概念书 / README）里写「数据不上传云端」或「支持离线运行」——那与实现相反，且会被评委对照演示站戳穿。可以写的是「数据可完整导出、不被锁定」。真本地优先若将来要做，须作为独立工程重新立项，并接受失去可分享网址。
