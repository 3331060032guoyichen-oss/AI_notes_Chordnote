## 1. 产品定位

产品名称暂时保留为 `AI Notes`。

它不是一个全屏聊天机器人，也不是传统文件夹式笔记软件。它是一个将原始资料逐步变成可复用知识，并帮助用户反复理解和记忆的学习工作台。

核心路径：

```text
原始资料 Raw
  -> AI 草稿 Draft
  -> 用户审阅 Review
  -> 知识页 Knowledge
  -> 关联 Relations
  -> 复习 Study
  -> 反向链接、图谱与知识检查 Graph / Lint
```

产品原则：

1. 原始资料可追溯，Raw 是不可变的事实来源。
2. AI 负责提炼、关联、生成练习和提出建议，用户负责确认意义。
3. 每一个 AI 结论都应该能够回到来源片段。
4. 知识库不是内容堆积，而是可以被查询、复习、修订和检查的系统。
5. 先让用户看懂和掌控，再增加自动化。

## 2. 研究结论与设计转译

### NotebookLM

NotebookLM 的关键模式是以用户提供的来源集为上下文，围绕来源进行带引用的问答、摘要和研究。它还将多种输入和音频等输出纳入同一研究流程。

转译到 AI Notes：

- 页面始终显示当前知识来自哪些 Raw。
- AI 回答、摘要和建议旁边显示来源引用入口。
- 资料阅读、知识整理和学习输出属于同一条工作流。
- 不把 AI 聊天单独做成产品中心，而是让 AI 贴近当前页面、选中文本和学习任务。

### Heptabase

Heptabase 将卡片、白板、双向链接、PDF 标注和 AI Tutor 结合起来，强调从资料到结构化理解的过程。

转译到 AI Notes：

- 知识页显示相关概念、来源和反向链接。
- Graph 不是装饰，而是知识页之间的可解释关系。
- 允许用户从一条资料进入概念，再进入相邻概念。
- Study 页面采用有目标的学习会话，而不是只有一段聊天记录。

### RemNote

RemNote 的优势是主动回忆：从文本生成闪卡、问答、填空和测验，并允许用户在接受 AI 生成内容前进行编辑。

转译到 AI Notes：

- Study 区要有闪卡、测验和 AI Tutor 三种明确模式。
- 生成的卡片必须经过用户确认，不直接写入知识库。
- 练习结果应回到知识页，指出薄弱概念和需要重新阅读的来源。

### Notion AI

Notion AI 将 AI 嵌入页面、数据库、搜索、会议记录和工作区操作中，说明 AI 更适合作为工作区内的行动层，而不是独立聊天页。

转译到 AI Notes：

- AI 操作出现在上下文面板和编辑区域附近。
- AI 建议应该是可接受、可拒绝、可编辑的提案。
- 将来可以扩展到批量整理、知识检查和学习计划，但第一版不做无边界 Agent。

### Capacities

Capacities 使用对象和对象类型组织知识，而不是只依赖文件夹，并强调关联、反向链接和可查询的对象结构。

转译到 AI Notes：

- Knowledge 不只是一篇长文，应具备类型、主题、来源、关系和状态。
- 左侧导航使用工作区入口，知识页内部使用对象属性和链接。
- 未来可以将人物、概念、课程、论文和项目作为不同类型的知识对象。

## 3. 视觉方向

### 设计关键词

安静、可信、可阅读、像研究桌面、轻量编辑器、带有纸张感但不复古、克制的 AI 感。

### 视觉决策

- 延续当前项目的米白背景、墨色文字、细边框和低饱和森林绿。
- 采用浅色优先，不使用紫色或蓝色渐变作为 AI 视觉捷径。
- 不使用玻璃拟态、霓虹发光、深色网格背景和大面积装饰性渐变。
- 不做传统 SaaS 的三张等宽卡片首页。
- 页面应更像一个高质量的学习工作室，而不是营销页面。
- 使用一套统一圆角，建议主要容器 `14px`，小控件 `8px`，不要每个组件使用不同圆角。
- 使用细边框、低强度阴影和足够留白表达层级。
- 避免纯黑和纯白，保证正文、辅助文字和边框均有足够对比度。

### 推荐设计变量

请优先复用项目已有变量。如果变量缺失，再补充类似以下的语义化变量：

```css
:root {
  --paper: #f4f1eb;
  --surface: #fbfaf7;
  --surface-raised: #ffffff;
  --ink: #26241f;
  --muted: #706a60;
  --line: #ded8ce;
  --line-strong: #c9c1b5;
  --accent: #566b55;
  --accent-strong: #435642;
  --accent-soft: #e5ebe1;
  --warning: #a7763e;
  --danger: #a3564c;
  --radius: 14px;
}
```

字体建议：优先使用项目当前字体体系；如果需要调整，使用 Geist 或系统无衬线字体，并为中文提供 `Noto Sans SC` 或系统中文字体回退。不要把 Inter 作为唯一的视觉选择。

## 4. 信息架构

桌面端采用三栏工作区：

```text
左侧导航 240px
  -> 中央主工作区 680px 至 820px
  -> 右侧上下文 AI 面板 300px 至 340px
```

### 左侧导航

顶部：

- AI Notes 标识
- 当前工作区切换
- `+ 新建资料` 主入口

主导航：

- 今日学习
- Inbox 待整理
- Knowledge 知识库
- Study 复习
- Graph 关系图谱
- Lint 知识检查

底部：

- 最近访问
- 设置
- 数据状态提示

导航要求：

- 当前入口必须明显，但不要使用高饱和色块铺满整个侧栏。
- 对 Inbox、待确认提案、知识检查显示真实数量。
- 导航标题使用中文，代码和数据字段继续使用英文命名。
- 移动端将左侧导航折叠为抽屉或底部导航，不保留固定 240px 侧栏。

### 中央主工作区

中央区域是用户阅读、编辑和确认的主要位置。它不能被聊天内容挤压。

统一包含：

- 面包屑或当前位置
- 清晰的页面标题
- 内容类型和状态
- 来源或关联对象入口
- 主要内容
- 次要操作

### 右侧上下文 AI 面板

右侧面板只显示与当前内容相关的 AI 操作：

- 询问当前页面
- 解释选中内容
- 提炼关键概念
- 建议关联知识
- 生成学习卡片
- 生成小测验
- 检查矛盾、孤立页和缺少来源的内容

每一项 AI 输出都必须显示：

- 生成内容
- 来源引用
- `接受`
- `拒绝`
- `编辑后接受`

不要让右侧面板成为一个无限滚动的通用聊天窗口。默认显示上下文操作和最近一条结果，用户主动展开后才显示完整记录。

## 5. 页面与交互规格

### 5.1 今日学习首页

目标：用户打开产品后，立即知道今天该继续什么。

布局建议：

- 顶部是一句简洁问候和当前学习目标，不做巨型 Hero。
- 左侧大区域显示 `继续学习`，直接进入上次未完成的知识页或学习会话。
- 右侧窄区域显示 `待确认`，包括 AI 草稿、关系建议和待处理的知识检查。
- 下方使用不等宽布局显示最近资料、知识库健康度和最近复习概念。

数据来源：

- 最近 Raw
- 最近 Knowledge
- 未确认 Draft
- 未处理 Relation
- Lint 结果

空状态：

- 没有资料时显示明确的 `导入第一份资料` 操作。
- 没有待办时显示简短的完成状态，不显示空白卡片。

### 5.2 Raw 资料阅读页

目标：让用户阅读原始资料，并知道它如何进入知识库。

页面结构：

1. 标题、来源类型、创建时间、字符数。
2. 原文阅读区，保持良好的行宽和段落间距。
3. 右侧显示目录、提取出的概念和已生成的 Draft。
4. 选中文本后提供 `解释`、`加入笔记`、`生成卡片` 和 `关联知识`。
5. 每个从原文提取的结果都能跳回原文位置。

注意：Raw 原文不可被 AI 直接改写。用户可以创建笔记和标注，但不能让 AI 静默覆盖原文。

### 5.3 Draft 审阅页

目标：让用户快速判断 AI 的提炼是否值得写入知识库。

建议布局：

- 左侧显示来源标题和原文锚点。
- 中央显示 AI 生成的标题、摘要、关键点、实体和关系建议。
- 每条建议都显示来源证据。
- 右侧显示提案状态和操作。

交互：

- 支持逐条接受、拒绝、编辑后接受。
- 提供 `接受已选`，不要默认提供不可逆的 `全部接受`。
- 取消操作不应修改持久化数据。
- 接受后才创建或更新 Knowledge、Relation 或学习卡片。
- 已处理的提案显示时间和处理人，避免重复确认。

### 5.4 Knowledge 知识页

目标：呈现可长期复用的知识，而不是一次性 AI 回复。

页面结构：

1. 标题、类型、状态、最后更新日期。
2. 一句话摘要。
3. 正文内容，优先可读性和段落结构。
4. 关键概念和标签。
5. 来源列表，每个来源可展开引用片段。
6. 反向链接和相关知识。
7. 变更历史和待处理建议。

知识页顶部建议显示状态：

- 已确认
- 待审阅
- 来源不足
- 可能有矛盾
- 已过期

知识页不应将所有字段压缩成密集表格。正文、来源和关系要有明显的视觉层级。

### 5.5 Study 学习页

目标：将知识库转化为可执行的主动回忆练习。

第一版实现三个模式：

1. 闪卡：问题在前，答案在后，支持显示答案、标记掌握程度。
2. 小测验：单选、简答或填空，答案必须能回到知识页和来源。
3. AI Tutor：围绕当前知识页或选定资料进行问答、追问和解释。

规则：

- AI 生成的卡片先进入待确认队列。
- 练习页面显示当前概念和来源，不要只显示抽象分数。
- 复习结束后显示需要重新阅读的知识页。
- 第一版可以记录简单的学习状态，不要过早实现复杂的间隔重复算法。
- 避免游戏化徽章、彩色能量条和虚假的成就感。

### 5.6 Graph 关系图谱

目标：帮助用户发现知识之间的结构，而不是展示装饰性节点。

第一版：

- 使用真实 Knowledge 和 Relation 数据生成节点。
- 支持按类型、状态和来源过滤。
- 点击节点打开知识页摘要。
- 显示孤立节点和关系密集区域。
- 提供列表视图作为图谱的可访问替代。

如果真实图谱能力暂时不足，先做关系列表和小型连接视图，不要使用没有数据支撑的模拟图。

### 5.7 Lint 知识检查页

目标：让知识库能够自我检查。

第一版检查项目：

- 没有来源的知识页
- 没有反向链接的孤立知识页
- 可能重复的知识页
- 关系指向不存在的对象
- 可能互相矛盾的结论
- 长期未更新的内容

每个问题都要有：问题说明、受影响页面、来源依据和建议动作。不要只显示一个红色数量。

## 7. 数据与 API 边界

### 必须保留

- Raw 数据不可变。
- Draft 只有在用户确认后才能影响 Knowledge。
- Relation 的创建和删除必须可追溯。
- 现有的 Wiki 内容继续从 `data/wiki.json` 或对应 API 读取，不要复制到 JSX。
- 现有 API 返回结构尽量保持兼容。

### 建议新增的领域对象

第一阶段只建立类型和 UI 需要的最小字段，不要一次实现完整后端：

```ts
type SourceAnchor = {
  rawId: string;
  quote?: string;
  start?: number;
  end?: number;
};

type Proposal = {
  id: string;
  kind: 'knowledge' | 'relation' | 'flashcard' | 'quiz' | 'lint';
  status: 'pending' | 'accepted' | 'rejected' | 'edited';
  sourceAnchors: SourceAnchor[];
  targetIds?: string[];
  content: unknown;
  reason?: string;
  createdAt: string;
  resolvedAt?: string;
};
```

如果当前后端还不支持 Proposal 持久化，先使用明确的前端状态完成交互骨架，并在代码中标记接口边界。不要假装已经完成真实持久化。

## 8. 响应式要求

至少验证以下尺寸：

- 移动端：390 x 844

- 支持 `prefers-reduced-motion`，减少非必要动画。

## 9. 动效要求

动效强度保持克制，服务于状态变化和空间关系：

- 页面和面板进入使用短距离透明度与位移动画。
- 接受提案后使用轻量状态反馈。
- 切换 Study 模式时使用清晰但短暂的过渡。
- 不使用无限循环装饰动画。
- 不使用会影响阅读的文字漂浮、光晕或视差。
- 优先使用 `transform` 和 `opacity`，避免影响布局的动画。

## 10. 实施顺序

请按以下阶段执行，每阶段完成后先验证再进入下一阶段。

### Phase 1：工作区骨架

- 建立三栏 AppShell。
- 把现有入口迁移到左侧导航。
- 将当前 Raw、Knowledge、Relations、Graph、Wiki 内容接入新的视觉结构。
- 完成桌面端、移动端和空状态。

通过标准：旧有数据仍能显示，导航可用，页面不依赖假数据。

### Phase 2：来源阅读与审阅

- 完成 Raw 阅读页。
- 完成 Draft 审阅页。
- 添加来源引用、接受、拒绝和编辑后接受的视觉交互。
- 先复用现有 API，缺失的 Proposal API 只建立清晰占位边界。

通过标准：取消不持久化，确认后才改变知识数据，来源引用可见。

### Phase 3：知识页与上下文 AI

- 完成 Knowledge 详情页。
- 完成来源、反向链接和相关知识模块。
- 完成右侧 Context AI Rail。
- AI 入口必须贴合当前页面和选中内容。

通过标准：AI 面板不是独立聊天页，所有建议均有来源和操作状态。

### Phase 4：学习模式

- 完成闪卡。
- 完成小测验。
- 完成以当前知识页为上下文的 AI Tutor 外观和交互骨架。
- 记录最小学习状态。

通过标准：用户能够从知识页进入练习，并能回到来源和知识页。

### Phase 5：图谱、Lint 与打磨

- 用真实关系完善 Graph。
- 完成知识检查列表。
- 添加搜索、过滤、键盘操作和移动端细节。
- 统一所有加载、空、错误和成功状态。

通过标准：系统能够指出至少一类真实知识问题，并提供可执行动作。

## 11. 明确不要做的事情

- 不要把产品改成普通的 ChatGPT 聊天界面。
- 不要使用紫色 AI 渐变、玻璃卡片、霓虹光晕或深色科技网格。
- 不要用三张等宽营销卡片替代真实工作流。
- 不要硬编码文章内容、知识节点或关系图来制造完成感。
- 不要修改 Raw 原文来迎合 AI 输出。
- 不要在没有持久化能力时声称操作已经保存。
- 不要第一阶段就引入向量数据库、复杂 Agent、OCR 或远程认证。
- 不要为了视觉重做而破坏现有 API 和数据结构。
- 不要加入没有明确学习价值的徽章、排行榜和装饰性进度条。
