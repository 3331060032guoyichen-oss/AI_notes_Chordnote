# AI Notes —— 交接给协作者的操作说明

> 用途：把「建一颗自生长的知识库」的改造任务交给别人（人或 AI 编码助手）。任务清单于 2026-10-12 按新决策重排，见第六节。
> 对方大概率也是 vibe coding，所以本文档同时给出「环境与红线」和「可直接粘贴的提示词」。

---

## 一、先给对方的 30 秒背景

- 项目：AI Notes，面向大学生的**自生长知识库**：写下笔记 → AI 提出建议 → 用户点一下采用 → 链接 → 网络越用越大。用户只面对「笔记」一种对象。校赛 Demo。
- 技术栈：Next.js 15（App Router）+ React + TypeScript + Drizzle ORM + Neon PostgreSQL，部署在 Netlify（GitHub 推 `main` 自动构建）。
- 仓库：`https://github.com/3331060032guoyichen-oss/ai-notes_demo.git`（公开仓库，克隆不需要权限；**推送需要仓库所有者把你加成 collaborator**）。
- 线上站点：`https://hilarious-kheer-89a440.netlify.app`
- 权威说明：仓库根目录的 `AGENTS.md` 是给 AI 助手的入口手册（决策记录、已删除功能、已知坑都在里面）。**动手前先读它**，不要只读 `docs/` 里的旧文档。

## 二、拿到代码并跑起来

```bash
git clone https://github.com/3331060032guoyichen-oss/ai-notes_demo.git
cd ai-notes_demo
pnpm install                 # 必须用 pnpm（packageManager: pnpm@11.25.0），不要用 npm/yarn
```

环境变量：把 `.env.example` 复制成 `.env.local`，然后按下面填。

| 变量 | 必填 | 说明 |
|---|---|---|
| `DATABASE_URL` | 是 | Neon **dev 分支**的池化连接串（host 里带 `-pooler`）。**必须由项目所有者私下给你，不要贴进仓库、issue 或聊天记录** |
| `DEEPSEEK_API_KEY` | 否 | 只有调试 AI 端点才需要；不填时 `/api/organize` 与 `/api/assistant` 返回 503，其余功能正常 |

```bash
pnpm dev                     # http://localhost:3000
```

注意：不要一边开着 `pnpm dev` 一边跑 `pnpm build`，两者共用 `.next/` 会互相覆盖。

## 三、红线（违反这些会出事故）

1. **只能连 Neon 的 dev 分支。** production 分支的连接串不要索取、不要配置、不要连接、不要执行任何 SQL。仓库里的 `.env.local` 就是你唯一的数据库入口。
2. **不要提交任何 `.env*` 文件**（`.gitignore` 已经挡住全部 `.env*`，只放行 `.env.example`）。不要把连接串、API Key 写进代码、注释、文档或提交信息。
3. **不要手改或删除 `drizzle/` 下已有的迁移文件**（`0000`–`0003` 已经在 dev 执行过）。需要新表/新列时，走 `pnpm exec drizzle-kit generate` 生成新迁移，**把生成的 SQL 发给项目所有者复核后**，再在 dev 分支执行。
4. **不要碰 `production` 分支、不要改 Netlify 的环境变量**，除非项目所有者明确要求。
5. **不要为了"看起来干净"删数据**。发现脏数据先报告，由所有者决定。

## 四、开发与自验流程

每条任务都按这个顺序做完再提交：

```bash
pnpm exec tsc --noEmit           # 类型检查
pnpm build                       # 生产构建（退出码 0，Warning 可忽略）
pnpm dev                         # 另开终端启动
pnpm test                        # 回归测试：60 项断言，必须全绿
pnpm verify:db                   # 校验数据库结构（11 张表 / 11 个 CHECK / 8 个外键）
```

- `pnpm test` 需要服务在跑（默认 `http://localhost:3000`）；它会自己造数据、自己清理，结束时打印「清理后库内为 0」。
- 想验证线上而不是本地：`REGRESSION_BASE_URL=https://hilarious-kheer-89a440.netlify.app pnpm test`（PowerShell 用 `$env:REGRESSION_BASE_URL="https://..."` 再 `pnpm test`）。
- **不可跳过**：改了 UI 就必须真的在浏览器里点一遍（本地或线上），不能只看代码。

## 五、提交与部署

1. **建议用分支 + Pull Request**，不要多个人直接往 `main` 推：`git checkout -b fix/声音浮层遮挡`，改完 push，开 PR，由项目所有者合并。
2. 提交信息写清「改了什么、为什么」。一个提交只做一件事，别把 5 个不相关的修改塞进一次提交。
3. 合并到 `main` 后 Netlify 会自动构建并发布，**大约 1–3 分钟生效**。
4. 上线后必须验证：打开线上站点跑一遍改动涉及的路径；接口相关改动再跑一次 `REGRESSION_BASE_URL=... pnpm test`。
5. 部署的坑：**不推送 = 线上一直是旧代码**，而且旧代码不会报错，只是表现不对（历史上就这么掉线过一次，见 `AGENTS.md` 决策记录）。判断线上是不是最新代码：往 dev 库插一条数据，看线上接口能否读到。

## 六、任务清单（2026-10-12 重排，取代旧 T1–T11）

目的：建一颗**自生长的知识库**（见 `ROADMAP.md`）。每条都给出「目标 / 改哪里 / 要做 / 验收」。**一次只做一条，做完验证再做下一条。** 依赖顺序：N1 → N2 → N3 / N4 → N5 → 其余。

### P0 —— 阶段一（10.16 前）

**N1. 口令门禁 + 预置演示数据 + 输入上限 + 配置 Key**（先门禁，后放 Key）

- 目标：陌生人拿到网址也读不到、清不掉数据；评审打开时看到的不是空库；放出 Key 后不被刷爆额度。
- 背景：`AGENTS.md`「使用范围」决策是小范围可信用户 + 共享口令，**不做账号、不做每人一个库**。仓库与文档是公开的，站点网址已在其中，所以门禁必须先于放 Key。
- 改哪里：新增 `middleware.ts`；新增环境变量 `ACCESS_PASSCODE`；`app/page.tsx` 工作台入口；新增 `scripts/seed-demo.mjs` 与 `seed/demo-notes.json`；`app/api/organize/route.ts`、`app/api/assistant/route.ts`。
- 要做的：
  1. 门禁：`ACCESS_PASSCODE` 有值时，`/api/**` 在没有有效 cookie 时返回 `401`（统一错误格式）；cookie 由 `POST /api/unlock { passcode }` 校验后种下（httpOnly，`SameSite=Lax`，值为口令的哈希，常量时间比较）。**未设置 `ACCESS_PASSCODE`（本地、脚本）时门禁关闭**，回归测试不受影响。落地页保持公开；进入工作台时若返回 401，在原位显示一个只有一个输入框的"访问口令"面板。
  2. 预置演示数据：`seed/demo-notes.json` 已给出 8 条示例笔记和 5 条链接。`scripts/seed-demo.mjs` 通过现有服务层（**不要直接写 SQL**）创建 raw + 笔记 + 链接，**按标题幂等**，已存在则跳过；只连 dev 分支。新增命令 `pnpm seed:demo`。
  3. `organize` / `assistant` 加输入长度上限，超限返回 400（沿用 `TEXT_TOO_LONG` 的错误风格）。
  4. 项目所有者在 DeepSeek 平台设置额度上限作为兜底；之后再配 Netlify 的 `DEEPSEEK_API_KEY` 与 `ACCESS_PASSCODE`。
- 暂不做：按身份计数限流、每人独立的库、账号体系。
- 验收：线上无 cookie 访问任何 `/api/*` 返回 401；输入正确口令后进入工作台，看到 8 条示例笔记；本地不设 `ACCESS_PASSCODE` 时行为与现在一致，`pnpm test` 仍全绿。

**N2. 一条笔记：新建 / 编辑 / 删除**

- 目标：用户只面对"笔记"；写下即保存；删除前明确二次确认。
- 改哪里：新增 `POST /api/notes`（`{ text }` → `201 { knowledge }`），在**同一事务**创建 `raw_notes` 与 `notes`（标题取正文首行 ≤40 字，空则"未命名笔记"；先检查 `INVALID_SUMMARY` 的校验，必要时允许空摘要）；新增 `DELETE /api/knowledge/:id`；`app/page.tsx`：左栏去掉"原始记录"分组，只留"笔记"（默认按更新时间排序，这**不是**被否决的"最近"分组）与"标签"；`Tab` 联合类型去掉 `raw` 与 `draft` 变体，"新建笔记"视图改为直接进入一条空笔记的编辑状态。
- 要做的：
  1. 编辑区：Markdown 文本域 + 预览切换；输入后防抖约 800ms 自动保存，失焦立即保存；`PATCH` 带 `version`，遇 `409 VERSION_CONFLICT` 提示"另一处已修改，请刷新"。
  2. 删除：先弹出明确的二次确认；确认后的存储与查询策略在实现该接口时再确定。
  3. 不新增富文本编辑器依赖。
- 验收：新建 → 刷新仍在；连续输入只触发少量保存请求；删除前出现二次确认；`pnpm test` 全绿（新增对 `/api/notes` 与删除的断言）。

**N3. AI 建议：展示 → 采用**

- 目标：保存后 AI 的整理结果以"建议"呈现，用户点一下采用；不再有六字段审阅表单。
- 改哪里：`app/api/organize/route.ts` 与 `lib/deepseek.ts`（增加 `knowledgeId` 参数，按笔记当前内容整理；提示词附已有概念名前 50 个）；`app/page.tsx` 右栏「助手」块（里面展示 AI 建议）。
- 要做的：
  1. 笔记首次保存且内容足够长时自动请求一次建议；之后只在用户点"整理"时请求，不要每次编辑都调。
  2. 建议以行呈现：摘要、要点、概念、整理版正文（并排对比）。每项一个"采用"，另有"全部采用"。采用 = `PATCH /api/knowledge/:id`（带 `version`）。
  3. 建议不持久化；刷新后消失，可重新请求。采用前标注"AI 建议"，采用后与用户内容无异。
  4. 失败文案按"发生了什么 + 内容是否安全 + 下一步"：例如"建议暂时没有提出，笔记已保存，请稍后重试。"
- 验收：新建一条课堂笔记后右栏出现建议；点"采用"后摘要和概念写入笔记并可在刷新后看到；不点则笔记字段保持不变；整理版采用后可通过修订回退。

**N4. 有向出链 / 反链 + 右栏 + 选中文字建链接**

- 目标：阶段一要求的出链、反链、"勾选内容建立链接"。
- 改哪里：`lib/services/*` 的关系服务（去重改为有序对）；`GET /api/knowledge/:id/backlinks`（在原有 `backlinks` 之外**增加** `links: { relationId, sourceId, reason }[]`，保持向后兼容）；`app/page.tsx` 右栏。
- 要做的：
  1. 右栏"出链 / 入链"两块（只显示有内容的块）；入链条目显示链接理由（即选中的原文片段）。
  2. 在编辑区选中文字，出现小浮层"链接到…"：可搜索已有笔记标题；确认后 `POST /api/relations`，`reason` = 选中片段（截断到约 200 字）。
  3. 浮层里另有"把选中内容变成新笔记并链接"（调用 `POST /api/notes`，再建链接）。
  4. 同一对笔记只保留一条链接，理由取首次选中的片段。
- 验收：A 中选中一句话链到 B → A 的出链有 B，B 的入链有 A 且显示那句话；反向再建 B→A 会得到第二条独立链接；已更新回归断言；"空状态"有文案。

**N5. 旧知识重现：「可能相关」**

- 目标：写作时，右栏自己冒出"你以前写过相关的"。这是自生长的核心。
- 改哪里：`app/page.tsx` 右栏第三块；AI 候选复用 N3 的建议（`relatedKnowledge`）。
- 要做的：把三种来源**合成一个列表**，每行 = 笔记标题 + 一行理由 + "建立链接"。已链接的不出现。
  1. **标题被提到**（本地计算，不调 AI）：其他笔记标题（长度 ≥2）出现在当前正文 → 理由写"正文提到了「标题」"；建立链接时 `reason` 取包含该标题的那句话。
  2. **共享概念**：与当前笔记共享至少一个概念 → 理由写"都讲到「概念」"。
  3. **AI 候选**：来自 N3 的 `relatedKnowledge`，理由用模型给出的原因。
  同一条笔记命中多种来源时合并成一行，理由并列。点击标题打开该笔记。
- 另：导航底部显示成长计数"笔记 N · 链接 M · 孤立 K"。
- 验收：已有笔记「梯度下降」；新写笔记正文提到"梯度下降"，右栏"可能相关"立刻出现它；点"建立链接"后链接数 M +1，该行消失；在示例数据里，「学习率」（孤立）会因为被「梯度下降」提到而出现在其"可能相关"里。

硬性约束：
