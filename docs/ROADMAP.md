# Roadmap

> 2026-10-12 重写。取代旧版的"目标 ↔ 现状 ↔ 差距"长表。权威现状以仓库根目录 `AGENTS.md` 与 `schema.md` 为准；本文只回答三件事：**我们要做什么、不做什么、接下来按什么顺序做**。

## 一、目的：一颗自生长的知识库

学生每写下一条笔记，这颗知识库就自己多长一点：补上摘要和要点，找到以前写过的相关内容，提出连接。学生只做"点一下"的决定，不填表单。

"自生长"必须能被验收，否则只是口号。三条判据：

1. **写完即有反馈**：保存一条笔记后，不需要任何额外操作，右栏就出现与已有笔记的关联线索。
2. **接受即变大**：每接受一个建议，知识网络里的笔记数或链接数真的增加，并且下次写作时被用上（旧知识重新出现）。
3. **不越权**：AI 在用户不知情时，不改动正文，也不改动结构（链接、删除）。

## 二、生长循环（产品主线）

```text
写下 / 导入 ──▶ 保存即成为笔记
                    │
                    ├─▶ AI 建议（摘要 / 要点 / 概念 / 整理版 / 候选链接）  ← 展示，不自动写入
                    ├─▶ 本地线索（未链接提及 / 共同概念）                   ← 不调 AI，即时
                    ▼
              用户点一下"采用 / 建立链接"
                    ▼
              网络变大 ──▶ 右栏在下一次写作时重现旧知识 ──▶ 提问 / 复习取用 ──▶ 回到"写下"
```

确认成本分级（硬边界不变：AI 只提议、用户拥有最终决定权；变的是"确认要花多少力气"）：

| 动作 | 方式 |
|---|---|
| 摘要、要点、概念、关键词 | 保存后在右栏展示为"AI 建议"；点"采用"才写入笔记字段，可"全部采用" |
| AI 整理版正文 | 并排展示，点"采用"才替换正文；`note_revisions` 保证可回退 |
| 建立链接 | 点一下建立；选中文字建链接时，选中的片段存为链接理由 |
| 删除 | 必须二次确认 |

## 三、已定决策（2026-10-12）

1. **用户只面对"笔记"一种对象。** 笔记 = Knowledge 层；Raw 退到幕后，只作"原始出处"，界面不再有"原始记录"分组。因此不再需要 Raw 的界面编辑入口，也不需要"手动收录"。
2. **链接有方向。** 出链 = `source` 为当前笔记；反链 = `target` 为当前笔记。服务层去重由"无序对"改为"有序对"，不需要迁移。
3. **选中文字建链接**：选中正文片段 → "链接到…" → 选已有笔记（或把选中内容变成新笔记再链接）；片段写入 `reason`。
4. **AI 建议第一版不持久化**（沿用 `OrganizeDraft` 的临时性质）。核对 schema 后发现 `note_ai_metadata` 没有"要点""整理版正文"列，硬塞不如先不存；将来确有需要再迁移。
5. **检索不上向量库。** 笔记量级是几百条：先让模型从"标题 + 摘要目录"里挑出相关 id，再取这些笔记全文回答并带引用。超过约 300 条再换检索方案。
6. **访问控制：共享访问口令 + 预置演示数据**（沿用 2026-10-10「使用范围」决策：小范围可信用户，不做账号体系）。曾评估过 cookie 匿名身份并**否决**：评审每人一个空库，既看不到演示内容，也展示不了「旧知识重现」。
7. **主题：** 浅 / 深两套，手动切换。
8. **删除前必须经过明确的二次确认**；其他删除实现细节待实际开发时确定。
9. **右栏仍是四块**（沿用 2026-10-10 决策）：入链 / 出链 / **可能相关** / 助手。AI 建议并入「助手」；「未链接提及」扩展为「可能相关」——凡是未链接但相关的笔记（标题被提到、共享概念、AI 候选）合成一个列表，每行带理由。

## 四、明确不做（避免过度设计）

- `Note / Question / Concept / Card` 四类节点体系；将来需要题目、卡片时，用笔记的 `kind` 字段承载。
- 独立的 `Proposal` 实体、`RawRevision` 界面、复习 / 知识检查 / 今日学习页（旧 brief 中的 Study、Lint 已作废）。
- 图谱的时间轴回放、分组着色、四个力参数滑块；Canvas 渲染（节点少，用 SVG）。
- 声音首次询问浮层；落地页新增任何视觉主体或动效（首屏冻结，只修标题对比度）。
- Agent 工具调用循环（`search_notes / create_note …`）。将来若做，先只给只读工具，写操作一律走确认。
- 向量数据库、Embedding、复杂权限体系、路由重构。

## 五、现状摘要

已实现：Postgres（Neon + Drizzle）存储；Raw / Knowledge / Relation 的 API；`/api/organize`（DeepSeek 生成 Draft）；`/api/assistant`（`@` 提及式单轮问答）；工作台（文件树 + 标签页 + 右栏）；落地页（Three.js 水晶 + 界面音效）；60 项回归断言。

尚缺的与目标直接相关的几块：笔记的**删除**（只有 Raw 可归档）、有向出链 / 反链的界面、选中文字建链接、右栏的上下文块、全局搜索与提问、局部图谱、口令门禁与预置演示数据。

## 七、OCR 与插件线（阶段二）

- **OCR 是最贴学生的功能，但先做试验再承诺**：据我所知 DeepSeek 官方 API 不支持图片输入，需另选支持视觉的模型；MinerU 需要 Python 服务，放不进 Netlify 无服务器环境，其许可证也须先核实。建议用 5 张真实手写笔记照片做一天试验再决定方案。
- **网页剪切**：先做"粘贴网址 → 抓正文 → 作为一条笔记"，不做浏览器扩展。
