# 任务分发 · 线 ② 界面（编辑器 · 图谱 · 面板 · 主题）

> 这份文件是**独立可开工**的。你不需要读另外两份分发文件。
> 但在写第一行代码之前，**必须先把 `AGENTS.md` 读完**——特别是「实际技术栈」和「已删除的功能」两节。这个项目里"顺手加个库"是事故，不是优化。

## 你负责的这一条线是什么

**看得见的那一半**：编辑器、知识图谱、右侧面板、主题。数据层由另一条线提供，你只管消费接口。

## 开工前必须知道的事实

## 红线

1. **不要引入 Tailwind / 任何 UI 组件库 / 任何图标库。** 现有 3 个组件全是手写的。
2. **不要给 AI 单独做一套视觉语言。** 右栏是"跟随当前标签的上下文面板"，不是聊天框，也不要把它退回成全局聊天框。
3. **毛玻璃只能用在浮层**（命令面板、弹层、抽屉）。正文、侧栏、面板一律不透明。
4. **不要重建「今日学习 / 复习 / 知识检查」三个视图**，也不要新增独立的复习/学习页面。
5. **不要重建「参考库 / Wiki」层**。
6. **不要用 `react-force-graph-2d` 这类"图谱组件库"**——布局、渲染、交互绑在一起，定制成本高。**`d3-force` 是允许的**（它只做力学计算）。
7. **动效克制**：缓出、不弹跳。不要做装饰性渐变和大面积玻璃拟态。
8. **密度底线**：字号 15px、行高 34–36px，但**每屏可见条目数不低于 12 条**——"大气"不能变成"不好用"。

## 任务清单

### B1 · `[[` 双链的阅读态渲染与跳转 —— P0
**背景**：数据层会先做一个最小版——**保存时解析 `[[标题]]` 并写入 `links` 表**。你在这之上做**用户看得见的那部分**。
**目标**：阅读态里 `[[某知识页]]` 不再是六个字面字符，而是一个**可点击、能跳转**的链接样式；点不存在的标题时给出明确反馈（而不是静默失败）。
**依赖**：数据层的最小版先落地（如果还没，你可以先用假数据把渲染做出来）。
**交付物**：`app/page.tsx` 里的渲染改动 + `app/globals.css` 里的链接样式。
**验收标准**：已有的 `[[...]]` 在阅读态渲染成链接样式；点击能跳到对应的知识页标签；hover 有克制的视觉反馈；未解析的链接有区分样式（暗一点）；纯文本里出现的 `[[` 不会错误吞掉后面的正文。
**不要做**：**不要做编辑器里的实时自动补全弹层**。这是产品主人在校赛期间明确砍掉的东西——原生 `<textarea>` 上做弹层成本极高，收益在截图里看不见。你可以在**后续**单独提案做这件事。

### B2 · 知识图谱：从卡片网格变成真正的力导向图 —— P0（**这条线最重要的一件**）
**现状**：图谱现在是一堆 **CSS grid 卡片**（`.network-map` 用 `grid-template-columns`，节点靠 `node-position-{index % 6}` 换个宽度）。**没有连线、不能拖、不能缩放**。而产品叫"知识网络"，这是最说不通的一处。
**目标**：真正的力导向图。**对标 Obsidian 的 Graph view**（`AGENTS.md` 2026-10-10 决策）。
**技术路线（已定，别改）**：**`d3-force` 做力学计算 + 自绘 Canvas 做渲染**。`/api/graph` 已经返回 `nodes{id,title,rawId}` + `edges{id,source,target,type,reason}`。
**你要补的第一步**：`/api/graph` **不返回节点的 degree（被引用次数）**，而"节点大小与被引用次数成正比"需要它——先在接口里加上（这条要和数据线打个招呼，别各自改）。
**要做到**：节点大小随被引用次数变化；滚轮缩放；拖拽平移；拖拽单个节点。
**可以留到以后**：筛选（按搜索词/标签/是否显示孤立点）、分组着色、局部图谱（只显示当前笔记的邻居 + 深度可调）、时间轴回放。**先把基础版做好，别一次全上。**
**验收标准**：节点和连线都画得出来；缩放到 0.3× 和 3× 都不崩；拖动节点后松手，布局会自然回稳；**空知识库时显示一个体面的空状态**（校赛演示第一眼看到的就是这个，别让它是一片空白）。
**不要做**：不要引入 `react-force-graph-2d`；不要把 `three` 用在这里；不要在切换标签页时丢掉布局状态导致每次重排。

### B3 · 反链面板正式化（右栏四块） —— P1
**背景**：右栏（宽约 312px）的**设计早就定了**（`AGENTS.md` 2026-10-10）：自上而下四块——**入链 / 出链 / 未链接提及 / 编辑助理**。但后端接口做好了**前端一次都没调用过**；现在知识页里那个"交叉引用"是从内存里的 `graph.edges` 过滤出来的，不是调接口。
**接口都已经有了**：`app/api/knowledge/[id]/backlinks/route.ts`、`app/api/knowledge/[id]/relations/route.ts`；"未链接提及"的接口由数据线提供（可能晚于你）。
**交付物**：右栏面板改造 + 对应的 CSS。
**验收标准**：四块都在；入链显示"哪些知识页指向了当前页"并能点击跳转；出链同理；未链接提及接口没就绪时该块显示"暂不可用"而不是报错；**切换标签时面板跟着变**（这是它和"全局聊天框"的区别）。
**不要做**：不要把它做成聊天框；四块的顺序和命名不要改。

### B4 · 明暗双主题 —— P2
**现状**：只有 `prefers-color-scheme` 跟随系统，没有手动切换。
**为什么值得做**：CSS 变量已经铺好了，成本低；校赛演示时"能不能切换"是个加分的小动作。
**验收标准**：手动切换开关存在且偏好能持久化；切换后**所有**面板颜色正确（重点检查图谱 canvas 的配色——它需要从 CSS 变量读色，不能写死）；不闪白。
**不要做**：不要做主题市场、不要做自定义颜色。

### B5 · 知识盲区地图的可视化 —— P2
**背景**：这是产品最核心的一个创意——**反复出错的知识点在图谱上被放大、染色**。
**依赖**：数据线（错题作为一种 `Source`）+ 插件线（从错题统计"某条知识页被关联了几次错"）。**两条都完成后你才干得动。**
**验收标准**：图谱支持"按出错次数上色"的视图；没有盲区数据时该视图**优雅地不出现**，而不是显示一片红。
**不要做**：不要为它单独做一个顶层视图。

### B6 · 编辑器 Live Preview（**最难，别从它起步**） —— P3，暂时不要做
Obsidian 的招牌手感是"语法符号在光标外隐藏、光标进入时露出"。**这一件的难度远高于本文件里其他所有任务之和**，而且原生 `<textarea>` 做不了，必须换 CodeMirror 6，等于重写整个编辑器。
**如果你真想挑战**，务必先知道这几个坑：中文输入法需要 `input.type.compose` 守卫（**少了它中文打字就废了**）；拖选时缺 `select.pointer` 守卫会闪烁；块级替换必须用 StateField 而不是 ViewPlugin，否则竖向布局会崩。
**建议**：先做完 B1–B4，再单独提案。
