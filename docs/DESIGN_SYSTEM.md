# Design System

## 去 AI 味原则

保持安静、自然、克制、有知识感和内容优先。避免赛博霓虹、紫蓝渐变、玻璃拟态、机器人插画和无意义粒子特效。AI 能力通过结果体现，而不是大量"AI"标签。

> **2026-10-17 修订：这条原则被两条新决策部分取代，看代码时别按上面那句下判断** ——
> ① 工作台背景加了一层**星尘**（tsParticles，极淡、只落在 `transform` / `opacity` 上），
> 纸面（内容卡与新建面板）改成**半透明**让星尘透出来 —— 见 AGENTS.md「在星空中读写」；
> ② 助手有了一个**拟物形象**（一把会呼吸的竖琴，纯内联 SVG）—— 见 AGENTS.md「整理助手的形象」。
> 仍然有效的部分：不用霓虹与紫蓝渐变、不放机器人插画、不做大面积玻璃拟态与光晕、AI 能力靠结果说话。

## 语言系统：私人知识编辑室

产品人格是冷静、诚实、克制的编辑伙伴。AI 只提交整理意见，用户拥有最终解释权；不得把推断写成事实，也不得暗示 AI 已替用户完成判断。

### 固定术语

| 内部概念 | 用户界面 |
|---|---|
| Raw | 原始记录 / 原话 |
| Draft | 整理稿 |
| Knowledge | 知识页 |
| Relation | 交叉引用 / 知识关联 |
| Graph | 知识网络 |
| Context AI | 编辑助理 |

推荐动词：留下、提出、审阅、确认、收录、修订、引用、移除。避免使用“生成完成”“一键完成”“智能赋能”等替用户下结论或夸大能力的表达。

整理稿必须称为“提议”，确认前使用“尚未收录”。成功文案说明内容当前状态；错误文案按“发生了什么 + 数据是否安全 + 下一步动作”书写，例如：“整理稿暂时没有提出。原始记录仍然安全，请稍后重试。”

面向用户使用自然中文，仅保留 `AI Notes` 品牌名和确有必要展示的技术标识。代码类型、API 字段、错误码与存储结构继续使用既有英文名称。

## Typography

使用清晰的 Display、Heading、Body、Secondary、Caption 层级，正文控制阅读宽度并保持合理行高，不滥用粗体或巨型标题。

**正文排版令牌**（2026-10-10 决策）：

> ⚠️ **现状与令牌不一致，以代码为准。** 实际生效的是 `app/globals.css` 里 `.reading-content` 的
> **14px / 行高 1.9 / 行宽 700px**（`.reading-summary` 15px），而不是下表写的 16px / 1.75。
> 下表是当时定的目标值，一直没落进 CSS；改字号时先量一遍真实值。**行宽 700px 与 4px 间距标度是落实了的**，
> 其余（`--row-height` 36px、界面字号 15px 等）是方向性约定。

| `--font-mono` | ui-monospace, Cascadia Code, Consolas, Sarasa Mono SC | 含中文等宽，避免中英混排错位 |

| `--h1…h6-size` | 1.618 / 1.462 / 1.318 / 1.188 / 1.076 / 1em | 近似黄金比阶梯，标题行高 1.3 |

### 大气简约 / 苹果产品设计感（2026-10-10 决策）

排版方向从"信息密集"调整为**大气、简约**，参考苹果产品的设计感。落地要点：

1. **留白优先于描线**。用背景层次（`--paper` / `--surface` / `--surface-raised`）区分区域，**不要**到处画 1px 边框。现有界面偏多线，这次要减。
2. **层级靠字号跨度，不靠装饰**。正文与界面字号之间的差距要明显（15 / 17 / 20 / 28 / 34px 这种跨度），不要用颜色和阴影制造层级。
3. **严格对齐**。所有元素对齐到 8px 网格（间距取 8 的倍数，允许 4px 用于行内微调）。
4. **动效克制**。缓出曲线，200–260ms，不弹跳、不缩放；`prefers-reduced-motion` 下取消位移。
5. **毛玻璃仅限浮层**：命令面板、弹层、抽屉。正文、侧栏、面板一律不透明。
6. **不做的**：装饰性渐变、大面积玻璃拟态、为了好看牺牲信息量。
7. **密度底线**：导航与列表行高 36px、界面字号 15px，但**每屏可见条目数不低于 12 条**。"大气"不能变成"看着舒服但不好用"。

标题的上间距必须**明显大于**下间距（比值 ≥ 2:1），否则标题看起来像属于上一段。段落、列表、代码块、引用块、表格、图片的逐项排版规范见改造报告 `03-信息架构与UI设计规范.md` 的 3.2 节。

首屏主标题使用极简无衬线字族，字重 800、字距 `-0.045em`、行高 `0.95`，字号 `clamp(46px, 8.4vw, 148px)`；第二行使用冷色渐变文字。字标为 `Chordnote`（品牌标记 `C`），不使用全大写装饰或混合字体。

## Layout

优先留白、分栏、列表、自然分组和弱边界。卡片仅用于独立信息或交互，不把所有内容都塞进卡片。

**四区结构**（宽度沿用现有令牌）：

| 区域 | 宽度 | 内容 |
|---|---|---|
| ① 导航区（左） | `--sidebar-width` 232px | 一级导航（Home / Knowledge / Graph / Agent）+ 当前空间的二级导航；Settings 由底部齿轮打开独立窗口 |
| ② 工作区（中） | 自适应 | Home 与 Knowledge 显示所属 Tab；Graph 与 Agent 直接渲染空间内容；正文宽度上限 `--measure` 700px |
| ③ **检查器（右）** | `--rail-width` 312px | Home 原始记录显示整理助手；Knowledge 显示知识页上下文；Graph 显示图谱参数；Agent 显示本次任务摘要；Settings 不显示 |
| ④ 全局层 | 浮层 | 命令面板（`Ctrl/Cmd+K`） |

> **右栏是检查器，不是全局聊天框。** Home 的原始记录用它显示整理助手；Knowledge 里它是入链 / 出链 / 未链接提及 / 编辑助理；Graph 里它是图谱参数；Agent 里它是本次任务摘要；Settings 不保留它。不要为 AI 做专属视觉语言。

响应式：≥861px 左栏 + 正文 + 检查器三栏；≤860px 检查器改抽屉；≤760px 单栏 + 移动端底部导航（四个空间，检查器按存在与否多一项）。

## Color

以中性色、一个主色、少量辅助色和状态色为主，颜色服务于信息层级、反馈和选择。

```css

--surface: #0a1122;
--surface-raised: #101a30;
--ink: #e8edf7;
--muted: #94a3b8;
--quiet: #64748b;
--line: rgb(148 163 184 / 18%);
--line-strong: rgb(148 163 184 / 32%);
--accent: #7c3aed;       /* 紫控制信号 */
--accent-strong: #6d28d9;
--accent-soft: rgb(124 58 237 / 20%);
--success: #2dd4bf;
--radius: 12px;
```

⚠️ **`:root` 已经是深色**，不再是"浅色 + 深色模式跟随系统"。工作台整体转深色是有意改版（提交 `32b5665` / `4dd5f61`，见 `docs/adr/0005`）。

原先还有一份 `@media (prefers-color-scheme: dark)` 覆盖块，写的是更早的深色变体（`--paper: #1d2026` / `--accent: #9aa7ff`）。那造成系统设为深色的用户看到另一套配色，**已于 2026-10-16 整块删除**。**本文件现在只有这一套令牌**——改配色时改这里和 `app/globals.css` 的 `:root` 即可，没有第二处。

装饰主色使用**紫 `#7c3aed`**。绿色、琥珀与珊瑚色只表达成功、警告与危险状态。禁止霓虹发光、大面积玻璃拟态等"AI 视觉捷径"。

> 注：本文件早先写有"禁止紫蓝渐变"，但落地页现在**刻意使用**冷色极光与紫蓝渐变作为其视觉语言（见 `docs/adr/0005`）。该禁令因此只适用于**工作台界面**，不适用于首屏落地页。

## Material

界面材料称为“粉末涂层面板”。通过低透明度微点、1px 刻线、内侧高光和带少量紫色相的短阴影表现触感，不使用仿金属照片、写实旋钮或卡通装饰。

首屏沿用同一材料语言：品牌标记、导航与卡片使用同一组冷色信号；区块以半透明深色面与 1px 弱边线分层，粒子与星尘从纸后透出。主按钮是紫→粉渐变胶囊，次按钮是玻璃描边；页面顶部有固定细噪点、极光光斑、流星与透视网格地面。

**首屏现状（2026-10-18 核对）**：`landing-crystal-scene.tsx` 已删除。首屏由三层组成：`landing-particle-field.tsx`（Three.js 发光粒子球壳、嵌套线框与光环，位于 Hero 右侧）、`landing-constellation.tsx`（Canvas 2D 星丛：4 个簇心、24 个节点、极淡连线）、`landing-stardust.tsx`（tsParticles 星尘，首屏与工作台共用配方）。整体沿用深色底、冷色极光与低透明度星尘，不再有水晶或静物图。

形状固定为三档：面板 12px、按钮 8px、状态标签 6px。首屏主按钮是渐变胶囊（`border-radius: 999px`，紫→粉），次按钮为玻璃描边；工作台内按钮仍按 8px 圆角。

控制分为三类：工作台主操作使用紫色键帽、2px 底边和短阴影；首屏入口使用渐变胶囊与紫色投影；次操作使用浅色面板、内侧高光和清晰边框；导航默认平面，仅在悬停、选中和按压时显露底板。

## Motion

主操作按下时下移 2px 并收拢阴影，导航和小按钮只下移 1px，释放后在 140ms 内回弹。禁用状态不产生按压反馈。`prefers-reduced-motion` 下取消所有位移，只保留颜色、边框与选中状态。

首屏是完整滚动的落地页：Hero 的 Three.js 粒子场缓慢旋转与呼吸，星丛随指针轻微排斥，星尘持续闪烁；滚动时 `--scroll-progress` 驱动玻璃卡浮起与光斑位移（`components/landing-page.tsx`）。全部动效只改 `transform` / `opacity`（粒子场改顶点与相机），`prefers-reduced-motion` 下停止位移、呼吸与流星。

视觉参数固定为 `DESIGN_VARIANCE 7 / MOTION_INTENSITY 8 / VISUAL_DENSITY 5`。桌面像素倍率最高 2；窄屏（≤820px）星尘与星丛减量。进入工作台后首屏整体卸载，不保留 WebGL 上下文。

## Sound

声音由 `components/interface-sound.tsx` 使用 Web Audio API 实时合成，不加载音频文件，也不依赖第三方包。内部 cue 为 `press`、`select`、`success`、`destructive`、`toggle-on` 和 `toggle-off`。

总音量上限约 3.5%，经过动态压缩，并设置 60ms 最短触发间隔。悬停、输入、滚动、加载循环与后台刷新不播放声音。普通操作通过 `data-sound` 声明基础反馈；保存、整理和收录必须在异步成功后显式播放 `success`，失败时不得播放确认音。

首次进入工作台只展示非模态询问，不自动出声。用户选择保存在 `localStorage` 的 `ai-notes:sound-preference`，值只允许为 `enabled` 或 `muted`。开关必须保留 `aria-pressed`；浏览器不支持 Web Audio 时禁用声音控制，但不得影响视觉反馈与业务流程。

## Components

Button、Input、Navigation、Dialog、Dropdown、Tabs、Card、Tag、Toast、Empty State、Loading 等组件保持一致的间距、边框和交互状态。

视觉组件继续由 `app/globals.css` 中的手写 CSS 与 CSS 变量控制。声音提供器、首次询问和持续开关位于 `components/interface-sound.tsx`。Three.js 只用于 Hero 粒子场；星丛是 Canvas 2D，星尘用 tsParticles。不使用 React Three Fiber、Drei、GSAP、物理引擎、UI 组件库、CSS 框架或额外音频资源。

## Organic Knowledge Network

**目标**：知识图谱采用自然布局、局部知识簇和不同密度，支持聚焦、拖动、缩放和类型筛选，避免规则网格与高饱和噪音。

**当前实现（2026-10-18 核对）**：`components/graph-view.tsx` 已落地。`d3-force` 只做力学计算，Canvas 自绘渲染；支持拖动、滚轮缩放、点节点出卡片、双击打开知识页、拖动即固定。右栏可调中心力 / 斥力 / 连线力 / 连线长度、节点大小与线宽，并可搜索节点、显示孤立点与连线方向箭头。

**仍未实现**：按查询词分组着色、局部图谱（只看当前笔记的邻居）、时间轴回放。

**设计目标与取舍（2026-10-10）：对标 Obsidian 1.14.4 的 Graph view。**

- 布局：力导向，四条参数可调（中心力 / 斥力 / 连线力 / 连线长度）
- 视觉映射：**节点大小与"被引用次数"成正比**（被引用越多越大）
- 交互：滚轮缩放、拖拽平移、悬停高亮该节点的连接、点击打开对应知识页
- 筛选：按搜索词、按标签、是否显示孤立点
- 分组着色：按查询词为一组节点指定颜色
- **局部图谱**：只显示当前笔记的邻居，深度可调（1 层 / 2 层……）——尚未实现
- 时间轴回放：按创建时间依次显示节点
- 技术：`d3-force` 做力学计算（**允许引入**）+ 自绘 Canvas 渲染；不用 `react-force-graph-2d` 这类组件库，不用 `three`

视觉上仍受本节开头约束：**自然布局、局部知识簇、密度差异，避免规则网格与高饱和噪音**。分组着色使用低饱和色，只用于区分，不做装饰。

## Knowledge Growth 动画

启动动画概念为 Seed → Connect → Growth → Accelerate → Dive → Desk → Home。动画应帮助用户理解知识网络的生长，并由滚动控制节奏。

**Knowledge Growth 启动动画仍未实现。** 首屏已经不是"滑动边框 + 欢迎窗口"，而是完整落地页：`components/landing-page.tsx` 的 Hero（Three.js 粒子场）+ 特点 + 工作方式 + 收尾，点击「进入编辑室」后写入 `localStorage` 并进入工作台（见 `ROADMAP.md` 的 C1 / C2）。
