# Design System

## 去 AI 味原则

保持安静、自然、克制、有知识感和内容优先。避免赛博霓虹、紫蓝渐变、玻璃拟态、机器人插画和无意义粒子特效。AI 能力通过结果体现，而不是大量"AI"标签。

## 语言系统：私人知识编辑室

产品人格是冷静、诚实、克制的编辑伙伴。AI 只提交整理意见，用户拥有最终解释权；不得把推断写成事实，也不得暗示 AI 已替用户完成判断。

### 固定术语

| 内部概念 | 用户界面 |
|---|---|
| Raw | 原始记录 / 原话 |
| Draft | 整理稿 |
| Knowledge | 知识页 |
| Relation | 交叉引用 / 知识关联 |
| Graph | 知识网络 |
| Context AI | 编辑助理 |

推荐动词：留下、提出、审阅、确认、收录、修订、引用、移除。避免使用“生成完成”“一键完成”“智能赋能”等替用户下结论或夸大能力的表达。

整理稿必须称为“提议”，确认前使用“尚未收录”。成功文案说明内容当前状态；错误文案按“发生了什么 + 数据是否安全 + 下一步动作”书写，例如：“整理稿暂时没有提出。原始记录仍然安全，请稍后重试。”

面向用户使用自然中文，仅保留 `AI Notes` 品牌名和确有必要展示的技术标识。代码类型、API 字段、错误码与存储结构继续使用既有英文名称。

## Typography

使用清晰的 Display、Heading、Body、Secondary、Caption 层级，正文控制阅读宽度并保持合理行高，不滥用粗体或巨型标题。

**正文排版令牌**（2026-10-10 决策，待落进 `app/globals.css`）：

| 令牌 | 值 | 说明 |
|---|---|---|
| `--font-text` | system-ui, Segoe UI, PingFang SC, Microsoft YaHei, Noto Sans SC | 界面与正文同族 |
| `--font-mono` | ui-monospace, Cascadia Code, Consolas, Sarasa Mono SC | 含中文等宽，避免中英混排错位 |
| `--text-size` | **16px** | 正文基准 |
| `--line-height-read` | **1.75** | 中文正文行高（参考值：Obsidian 1.14.4 用 1.5，面向拉丁字母；中文密度更高，上调） |
| `--p-spacing` | **1em**（16px） | 段落间距。中文**不用首行缩进**分段 |
| `--measure` | **700px** | 正文行宽上限。窗口变宽时增加留白，不要拉长行宽 |
| `--reading-margin` | 32px | 正文区左右内边距 |
| `--font-ui-smaller / small / medium / large` | 12 / **15** / 17 / 20px | 界面字号。导航项与标签用 **15px**（2026-10-10 从 13px 上调，见下）|
| `--h1…h6-size` | 1.618 / 1.462 / 1.318 / 1.188 / 1.076 / 1em | 近似黄金比阶梯，标题行高 1.3 |
| `--space-1…--space-12` | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48px | 间距标度，**一律取 4 的倍数**，不要随手写 13px |
| `--row-height` / `--icon-size` | **36**px / 16px | 树节点与列表项行高（从 28px 上调）。密度底线：每屏可见条目数 ≥ 12 |

### 大气简约 / 苹果产品设计感（2026-10-10 决策）

排版方向从"信息密集"调整为**大气、简约**，参考苹果产品的设计感。落地要点：

1. **留白优先于描线**。用背景层次（`--paper` / `--surface` / `--surface-raised`）区分区域，**不要**到处画 1px 边框。现有界面偏多线，这次要减。
2. **层级靠字号跨度，不靠装饰**。正文与界面字号之间的差距要明显（15 / 17 / 20 / 28 / 34px 这种跨度），不要用颜色和阴影制造层级。
3. **严格对齐**。所有元素对齐到 8px 网格（间距取 8 的倍数，允许 4px 用于行内微调）。
4. **动效克制**。缓出曲线，200–260ms，不弹跳、不缩放；`prefers-reduced-motion` 下取消位移。
5. **毛玻璃仅限浮层**：命令面板、弹层、抽屉。正文、侧栏、面板一律不透明。
6. **不做的**：装饰性渐变、大面积玻璃拟态、为了好看牺牲信息量。
7. **密度底线**：导航与列表行高 36px、界面字号 15px，但**每屏可见条目数不低于 12 条**。"大气"不能变成"看着舒服但不好用"。

标题的上间距必须**明显大于**下间距（比值 ≥ 2:1），否则标题看起来像属于上一段。段落、列表、代码块、引用块、表格、图片的逐项排版规范见改造报告 `03-信息架构与UI设计规范.md` 的 3.2 节。

首屏主标题固定使用极简无衬线字族，字重 700、字距 `-0.02em`、行高 `0.98`。桌面字号上限为 82px，移动端上限为 50px；标题与说明形成紧凑组块，不使用全大写装饰或混合字体。首屏 `AI Notes` 字标使用 18px、90% 白色不透明度，配合 36px 品牌标记。

## Layout

优先留白、分栏、列表、自然分组和弱边界。卡片仅用于独立信息或交互，不把所有内容都塞进卡片。

**四区结构**（宽度沿用现有令牌）：

| 区域 | 宽度 | 内容 |
|---|---|---|
| ① 导航区（左） | `--sidebar-width` 232px | 分组：**原始记录 / 知识页 / 标签 / 参考库**（四个；不做「最近」列表）|
| ② 工作区（中） | 自适应 | 标签页；正文宽度上限 `--measure` 700px |
| ③ **上下文区（右）** | `--rail-width` 312px | **跟随当前标签**的四块：入链 / 出链 / 未链接提及 / 编辑助理 |
| ④ 全局层 | 浮层 | 命令面板（`Ctrl/Cmd+K`） |

> **2026-10-10 决策：右栏是上下文面板，不是全局聊天框。** AI 是面板四块中的一块，与「谁引用了我」属同一类信息。不要为 AI 做专属视觉语言——它应与其他面板长得一样。理由：产品定位是 AI 增强知识管理，占满一整栏的聊天框会把它变成聊天机器人。

响应式：≥1280px 三栏常驻；900–1279px 左栏折叠为 48px 图标条、右栏改抽屉；<900px 单栏 + 抽屉。

## Color

以中性色、一个主色、少量辅助色和状态色为主，颜色服务于信息层级、反馈和选择。

**当前实现**（`app/globals.css` 的 `:root`，改动配色时请同步本节与代码）：

```css
--paper: #ecefeb;        /* 冷矿物白底色 */
--surface: #f5f7f4;
--surface-raised: #fcfdfb;
--ink: #20232b;          /* 石墨正文 */
--muted: #626975;
--quiet: #858d99;
--line: #cbd1d3;         /* 细刻线 */
--line-strong: #aeb7bd;
--accent: #4a5ac8;       /* 钴蓝控制信号 */
--accent-strong: #34439a;
--accent-soft: #e2e6fa;
```

另有 `@media (prefers-color-scheme: dark)` 覆盖块提供深色模式（跟随系统自动切换，**尚无手动主题切换**）。

装饰主色只使用钴蓝。绿色、琥珀与珊瑚色只表达成功、警告与危险状态。禁止霓虹发光、玻璃拟态、大面积灰色渐变和紫蓝渐变等“AI 视觉捷径”。

## Material

界面材料称为“粉末涂层面板”。通过低透明度微点、1px 刻线、内侧高光和带少量钴蓝色相的短阴影表现触感，不使用仿金属照片、写实旋钮或卡通装饰。

首屏沿用同一材料语言：品牌标记、就绪状态和入口键帽使用相同的控制信号与按压层级。揭示后的欢迎面板贴合取景框底边，只保留 12px 顶部圆角；面板使用 85% 深色基底与 12px 背景模糊，主操作改为纯白底深色字的几何键。静物图继续作为内容背景，并固定采用左上方柔光：球体、纸张与蓝图的投影统一落向右下，重叠纸层以接触阴影区分高度，朝向光源的纸边保留窄幅高光。页面不在左侧文字后方放置背板、灰色横条或局部遮罩，静物图必须完整露出；主标题包括原强调行在内统一使用纯白，并以 `2px 4px 15px`、90% 黑色的单层重阴影建立对比。左上说明同样使用纯白，只配轻量黑色阴影。最上层继续使用约 3.5% 的固定细噪点消除过度平滑。

首屏只允许一个额外的视觉主体：由 `landing-crystal-scene.tsx` 实时绘制的无色碎裂水晶。它位于右侧，与静物共用左上光源、右下接触阴影和克制的钴蓝折射；珊瑚色仅作为极少量环境反射。`/landing-crystal-poster-v1.png` 是 WebGL 初始化失败或上下文丢失时的透明降级海报。旧的 `/landing-optical-lens-v1.png` 仅为保留资产，不再渲染。禁止继续叠加球体、漂浮几何体、霓虹或全息彩虹。

形状固定为三档：面板 12px、按钮 8px、状态标签 6px。首屏欢迎面板因与取景框相接，底部圆角固定为 0；其中的白色主操作键使用 2px 小圆角。声音开关是唯一允许使用胶囊形内部状态的控件。

控制分为三类：工作台主操作使用钴蓝键帽、2px 底边和短阴影；首屏入口是例外，固定使用 60% 黑色磨砂玻璃、白色文字、6px 小圆角、10px 背景模糊和极弱白色边线，不使用渐变或蓝紫色。次操作使用浅色面板、内侧高光和清晰边框；导航默认平面，仅在悬停、选中和按压时显露底板。

## Motion

主操作按下时下移 2px 并收拢阴影，导航和小按钮只下移 1px，释放后在 140ms 内回弹。禁用状态不产生按压反馈。`prefers-reduced-motion` 下取消所有位移，只保留颜色、边框与选中状态。

首屏滑动框使用取景器式锁定反馈：以 20% 白色内描边和低强度钴蓝辉光建立边缘质感，框内背景最多模糊 4px，不额外压暗整张图片。框体从 `scale(1.018)` 收束到 `scale(1)`，同时以透明度渐入；减少动态效果模式下取消缩放，仅保留描边与模糊状态。

取景框出现时，顶部品牌与状态区域跟随揭示进度从完整不透明逐步降至 30%。它们保留空间定位，但不得与取景框和底部欢迎面板争夺视觉焦点。

首屏使用一个 Three.js 画布统一组织静物背景、水晶、投影与焦散，不劫持滚动，也不拆分多个 WebGL 视角。水晶由 20 个共享中心的三角锥碎片拼合，18 秒循环依次经过完整悬浮、缓慢碎裂、克制旋转、复原和稳定阶段；首尾姿态一致。桌面指针只改变约 4° 观察角，揭示编辑室时保留短距离推镜并降低水晶亮度。

视觉参数固定为 `DESIGN_VARIANCE 7 / MOTION_INTENSITY 8 / VISUAL_DENSITY 5`。桌面像素倍率最高 1.5；移动端最高 1.0、约 30fps 且关闭实时阴影。页面不可见、场景离开视口或进入工作台后暂停渲染。`prefers-reduced-motion` 下固定为轻度碎裂构图，不播放循环；WebGL 不可用时显示透明水晶海报和原静物背景。场景卸载时必须释放几何体、材质、纹理、环境贴图和渲染器资源。

## Sound

声音由 `components/interface-sound.tsx` 使用 Web Audio API 实时合成，不加载音频文件，也不依赖第三方包。内部 cue 为 `press`、`select`、`success`、`destructive`、`toggle-on` 和 `toggle-off`。

总音量上限约 3.5%，经过动态压缩，并设置 60ms 最短触发间隔。悬停、输入、滚动、加载循环与后台刷新不播放声音。普通操作通过 `data-sound` 声明基础反馈；保存、整理和收录必须在异步成功后显式播放 `success`，失败时不得播放确认音。

首次进入工作台只展示非模态询问，不自动出声。用户选择保存在 `localStorage` 的 `ai-notes:sound-preference`，值只允许为 `enabled` 或 `muted`。开关必须保留 `aria-pressed`；浏览器不支持 Web Audio 时禁用声音控制，但不得影响视觉反馈与业务流程。

## Components

Button、Input、Navigation、Dialog、Dropdown、Tabs、Card、Tag、Toast、Empty State、Loading 等组件保持一致的间距、边框和交互状态。

视觉组件继续由 `app/globals.css` 中的手写 CSS 与 CSS 变量控制。声音提供器、首次询问和持续开关位于 `components/interface-sound.tsx`。水晶场景只引入 `three` 与匹配类型，不使用 React Three Fiber、Drei、GSAP、物理引擎、UI 组件库、CSS 框架或额外音频资源。

## Organic Knowledge Network

**目标**：知识图谱采用自然布局、局部知识簇和不同密度，支持聚焦、拖动、缩放和类型筛选，避免规则网格与高饱和噪音。

**当前实现与目标的差距（如实记录，避免文档与代码不一致）**：

`app/page.tsx` 的图谱视图用 `node-position-${index % 6}` 把节点排进一个**固定 6 槽位的规则网格**，节点是卡片按钮，**不画连线**，也不支持拖动、缩放或聚焦。

也就是说：**当前实现恰好是本节要求避免的"规则网格"**，这一节描述的是待实现目标，不是现状。相关排期见 `ROADMAP.md` 的 B1 项。

**实现方式已定（2026-10-10）：对标 Obsidian 1.14.4 的 Graph view。**

- 布局：力导向，四条参数可调（中心力 / 斥力 / 连线力 / 连线长度）
- 视觉映射：**节点大小与"被引用次数"成正比**（被引用越多越大）
- 交互：滚轮缩放、拖拽平移、悬停高亮该节点的连接、点击打开对应知识页
- 筛选：按搜索词、按标签、是否显示孤立点
- 分组着色：按查询词为一组节点指定颜色
- **局部图谱**：只显示当前笔记的邻居，深度可调（1 层 / 2 层……）——**先做这个**，全库图谱后做
- 时间轴回放：按创建时间依次显示节点
- 技术：`d3-force` 做力学计算（**允许引入**）+ 自绘 Canvas 渲染；不用 `react-force-graph-2d` 这类组件库，不用 `three`

视觉上仍受本节开头约束：**自然布局、局部知识簇、密度差异，避免规则网格与高饱和噪音**。分组着色使用低饱和色，只用于区分，不做装饰。

## Knowledge Growth 动画

启动动画概念为 Seed → Connect → Growth → Accelerate → Dive → Desk → Home。动画应帮助用户理解知识网络的生长，并由滚动控制节奏。
