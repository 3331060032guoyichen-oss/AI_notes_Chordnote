# 界面与笔记 Agent 核查 · 2026-10-21

## 界面改动

以现有工作区和设计变量为基础，收紧了笔记、目录、搜索、设置与 Agent 面板的层级和间距。笔记正文保持直接编辑，空白编辑页不增加引导文案；知识页索引改为轻量列表。搜索支持范围筛选、键盘选择和焦点返回，设置弹窗统一了 Esc、焦点约束及关闭过渡。窄屏保留五项底部导航和 Agent 抽屉。

知音小人增加静息呼吸、眨眼、轻微笑容和指针跟随；工作态保留星云、拨弦与点击反馈。指针离开后视线回正；减少动态效果时停用持续动画；舞台离开视口或页面隐藏时暂停绘制。实际浏览器中已看到静息和真实请求期间的工作态，并验证跟随、回弹及减少动态效果。

视觉参考为 [Obsidian](https://obsidian.md/)、[Linear](https://linear.app/)、[Raycast](https://www.raycast.com/) 与 [Craft](https://www.craft.do/)；主要借鉴克制的编辑区、紧凑导航和键盘优先的查找方式。Claudian 的可核查功能来自其[官方仓库](https://github.com/YishenTu/claudian)。本机已启动 Obsidian，并确认启用 Claudian 2.3.13；当前环境没有可用的原生窗口输入工具，因此**没有完成在 Claudian 中输入同题并比较输出**，以下分数只评 Chordnote。

## 笔记使用者视角

由笔记使用者子 Agent 对代码、交互和三组隔离数据上的实际 DeepSeek Flash 结果评估。分数是这几组样例的定性判断，不能当成总体准确率。

| 范围 | 内容输出 | 上下文 | 整理归类 |
| --- | ---: | ---: | ---: |
| 产品设计审阅 | 6.5/10 | 5.5/10 | 5.5/10 |
| 三组实际运行 | 6.5/10 | 4.0/10 | 5.0/10 |

- 长资料：80 段过程记录之后才有最终结论。Agent 发现读取被截断并拒绝猜测，这是好的；但读取工具把截断内容称为“读完”，也没有继续读取的偏移能力。回答过长，用户仍需手工找尾段。`read_note` 的 4,000 字符上限、工具结果的 8,000 字节截断及目录上下文上限共同造成这一问题。
- 合并已有知识：Agent 正确提出更新已有页，没有另造近似页面，并保留两份来源路径。回答包含过多执行细节，且将原来源“未声称完全消除”强化成“两来源明确承认无法消除”，证据措辞需要更严。
- 批量整理三份 Raw：Agent 连续调用三次 `draft_knowledge`，分别识别论文、文章、书籍的目标类别；但运行结果只保留最后一份草稿，前两份无法在界面独立确认，且最终回答声称三份均待确认。优先修复草稿集合及每份独立确认、计数和结果核对。
- 一次真实界面提问要求“一句话说明并给出处”，回答包含核心观点、来源解释和冗长的运行说明；简短问答仍需更严格遵守长度要求。当前示例还把数值稳定性与输入敏感度混为一谈，需用更可靠的来源核对约束。

## 分类投诉核查

投诉的第一部分属实：新知识页由 `promoteFromSource` 固定写入 `wilki/concept/<id>.md`。整理稿只有 `rawCategory`，没有 Wiki 类别；把 Wiki 页改入其他目录需要后续单独执行分类。因此“新笔记都进 concept”与现有实现一致，自动 Wiki 归类尚未实现。

Raw 的情况取决于整理动作。确认**新建知识页**时，服务在同一事务内把关联 Raw 移入所选类别；隔离 API 实测 `books → raw/books`、`papers → raw/papers`。类别缺失时回退到 `raw/articles`，旧整理入口没有要求模型填写 `rawCategory`，因此容易出现大量 `articles`。确认界面有“来源分类”下拉框。

确认**把一份新 Raw 合并进已有知识页**时，`note_update` 只改写知识页正文，没有登记这份补充 Raw 与知识页的来源关系，也没有给它分类。隔离数据上实际批准并执行提议后，补充 Raw 仍是 `raw/<id>.md`；知识页仍只记录原始 `rawId`，补充 Raw 依旧被判作未整理。这一投诉也属实，但只适用于这条合并路径。测试没有触碰个人笔记库。

修复顺序建议：先把多草稿结果完整保留并让用户逐份确认；再给补充来源建立可查询关联，完成合并时分类并更新“已整理”判断；最后让 Wiki 类别进入整理稿和确认界面，并处理现有 `concept` 页的迁移。长资料读取需带“已截断/下一段”标记与分页，简短问答应压缩运行说明。
