## 评审重点

评分细则：选题价值与导向10分、创新性与原创贡献25分、技术实现与规范25分、完成度与可验证性20分、应用与传播价值10分、展示与答辩10分。创新、技术、验证合计70分，应优先展示可复现的知识整理闭环及学生的具体设计决策。

中心表述建议：面向大学生，构建由可编辑工作规则指导、由宿主权限控制、能保留来源和操作记录的知识整理 Agent。现有灵感不等于原创；具体规则设计、工程实现、交互和验证才是需要举证的贡献。

## 实际技术栈

| 层 | 实现 | 对用户的作用与来源 |
|---|---|---|
| 应用框架 | Next.js 15 App Router、React 19、TypeScript | 一套工程承载界面和本机后端，[依赖声明](../../package.json) |
| 界面 | 手写 CSS、自定义属性；Three.js、tsParticles用于视觉场景 | 统一排版、主题、落地页粒子；不是现成UI组件库拼装，[样式](../../app/globals.css)、[首屏粒子](../../components/landing-particle-field.tsx) |
| 编辑器 | CodeMirror 6、Lezer、YAML、KaTeX | 连续Markdown、语法预览、wikilink、属性和公式，[编辑器](../../components/markdown-editor.tsx) |
| 前后端连接 | 浏览器fetch，同源HTTP API，JSON请求和响应 | UI调用`/api/raw`、`/api/knowledge`、`/api/agent/organize`等，[调用入口](../../app/page.tsx) |
| 后端 | Next.js Route Handlers、Node.js、TypeScript服务层 | 路由处理请求，服务层执行归属、版本和业务规则，[Agent路由](../../app/api/agent/organize/route.ts)、[业务服务目录](../../lib/services) |
| 存储 | Drizzle ORM + PGlite | PostgreSQL的WASM版本运行在Node进程内，数据写本机目录，不要求外部数据库，[连接工厂](../../lib/db/client.ts)、[数据结构](../../lib/db/schema.ts) |
| Agent | DeepSeek Harness（dsh）+ Chordnote受控工具桥 | 多轮模型与工具调用；支持兼容API、Ollama、ACP外部Agent，[运行时](../../lib/agent/runtime.ts) |
| 图谱 | d3-force计算布局，自绘Canvas渲染 | 节点拖拽、缩放和跳转；图数据合并正式关系与已解析正文wikilink并去重，[图服务](../../lib/services/graph.ts)、[绘制](../../components/graph-view.tsx) |
| 桌面 | Tauri 2 / Rust + Next.js standalone + NSIS配置 | 桌面壳启动本机服务，复用Web界面，[配置](../../src-tauri/tauri.conf.json)；此次未构建或验收安装包 |

数据链路：界面 → fetch HTTP/JSON → Next.js路由 → 业务服务 → Drizzle → 本机PGlite。Agent另由服务端读取Schema、当前笔记和上下文，调用dsh；模型返回工具请求，由宿主检查权限后执行，再把轨迹和真实结果返回UI。当前整理接口最终返回JSON trace，不能描述为已实现SSE流式回传。

数据库本地化不等于所有模型推理离线。选云端模型时，任务所需文本会进入模型请求。Ollama配置的默认模型名是`qwen3:4b`，不证明仓库或安装包携带模型权重，见[配置](../../lib/ai/config.ts)。

## 关键实现建议

### 工作规则和执行权限分开

[Schema](../../lib/agent/Schema.md)规定Raw、Wiki分类、页面格式、摄入与查询方式；[manual](../../lib/agent/manual.ts)定义工具与权限；[loop](../../lib/agent/loop.ts)再次检查每次工具调用。用户可修改整理偏好，不能通过修改Schema扩大权限。这是比单纯展示长Prompt更有价值的实现。

演示：打开Schema，展示来源类别与知识页用途类别；改变一个简单输出偏好，保存后在下一次任务验证。不要声称Schema所有条款都由代码强制保证，模型对格式与语义的遵从仍需检查。

### 三档权限与提议状态机

只读只检索阅读；可提议生成草稿/待确认变更；完全允许在本轮任务范围内由宿主应用变更，旧会话待办不自动执行。Agent不能改写Raw正文，用户可编辑Raw并留审计。

[提议服务](../../lib/services/proposals.ts)含批准、执行、拒绝、过期状态，版本检查、幂等键和事务；[原文服务](../../lib/services/sources.ts)检查操作主体。注意：初次知识整理草稿和持久化proposals不是完全相同的数据对象，不能把所有Draft都说成一条proposals记录。

演示：默认可提议生成整理稿，先拒绝一项，再确认需要的项；展示确认前后知识库变化。可另录一次旧版本提议被拦截作为工程验证素材。

### 知识关系和来源可追溯

[Markdown解析](../../lib/documents/markdown.ts)与[文档引用服务](../../lib/services/documents.ts)负责链接解析；[图服务](../../lib/services/graph.ts)合并正式关联和正文链接。普通同名词出现不会自动成边；显式、可解析的`[[链接]]`可能直接形成图谱边，不需要再建立一条正式Relation。

演示：新资料与已有笔记产生有理由的联系，确认知识页后切图谱，再由节点返回知识页及Raw来源。优先用同一组材料贯穿视频，避免功能跳转形成碎片。

### 会话上下文与持久偏好

[会话](../../lib/agent/sessions.ts)保留进程内近期完整轮次，默认10轮，并受预算和6小时空闲回收约束；服务重启后失效。[检索](../../lib/agent/context.ts)按标题、路径和正文关键词排名取片段，不是向量数据库。[偏好](../../lib/agent/preferences.ts)限定Schema的用户偏好区块；[Schema持久化](../../lib/services/agent-schema.ts)用hash防止旧版本覆盖。当前知识文档、偏好和操作记录可在新会话重新读取，不等于永久保存所有聊天。

演示：用户明确提出长期偏好，确认写入；新会话读取已保存偏好。不要称为模型训练、无限记忆或完整聊天永久存档。

## 视频结构建议

按六分钟示例分配：0:00–0:30落地页与学生痛点；0:30–1:10创意来源及具体改造；1:10–1:40一张前后端架构图；1:40–4:10用同一组材料演示原文、整理、审阅、知识页、链接和图谱；4:10–4:50解释Schema、权限及记忆；4:50–5:25呈现测试、导出和真实试用成果；5:25–6:00说明学生分工、AI使用与后续边界。时长只是建议，比赛时限尚未提供。

落地页是入口，视觉部分建议不超过总时长的10%–15%。知音形象可结合真实工作/静息状态讲SVG前景和Canvas背景实现；文化灵感与交互含义属于设计贡献，不应挤占核心闭环演示。

## 原创与成果举证

逐项列出：借鉴了谁的理念或库、团队做了何种具体改造、哪位学生负责、有哪些源码/设计迭代/测试或录屏证据、AI辅助了什么以及学生如何核验。不能由仓库代码单独推断具体成员原创归属。

实际成果优先提供运行闭环、保存后重开、拒绝不生效、版本冲突处理、知识包导出等证据。效率、准确率、用户数没有实测不填数字。如做对照试验，应统一资料、任务和模型，记录人工整理时间、AI+审阅总时间、关联接受率和事实错误；清楚区分演示样例和真实用户试用。

## 概念书需校准的表述

- “永远逐项确认”改为默认可提议逐项确认，完全允许为本轮授权内执行。
- “从根本上避免幻觉”改为通过来源、审阅和权限降低错误内容进入正式知识库的风险。
- “内置Qwen3”改为支持通过Ollama接入Qwen3，除非能证明安装包携带权重并完成离线验收。
- “完全开源”需有可访问仓库、许可证和对应版本证据；本地存在Schema与MIT文件不证明已公开发布。
- “反链面板”“raw/inbox”等旧界面描述应按录制时的现版本调整。
- 原创贡献突出分类细则、执行约束、数据链路和交互设计，不把LLM Wiki三层、Schema或双向链接理念本身称为首创。
- 创意来源作者与Claudian版本需要依据原始来源核准，参见另附来源调研。
