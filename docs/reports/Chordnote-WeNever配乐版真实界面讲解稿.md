# Chordnote We Never 配乐版真实界面讲解稿

本稿在原评审稿基础上转化，建议约7—8分钟。真实网页操作贯穿全片，四张用户提供的图片承担来源、设计过程和角色设计的证据作用。音乐用于章节衔接和情绪推进，旁白保持清晰。本次未取得具体音频文件，时间仅为剪辑建议，不表示已经完成节拍分析。

叙事主线：一次记录怎样经过规则、Agent与学生审阅，进入可追溯的知识网络。每段都让评委看到问题、团队的具体设计以及对应的真实页面。

## 00:00—00:30 从记录开始

画面：直接从真实落地页开始，完整显示“Chordnote”和“你的长期AI知识架构师”。顺着网页滚动到“从记录开始。和理解一起生长。”，点击“进入工作台”。可用简短的文字浮现呼应课堂、阅读和灵感，保留网页本身的视觉。

口播：

课堂上的一行推导，书页里的一句批注，深夜里一个突然想通的念头。

我们把它们认真记下，放进笔记、文件夹和收藏。

但记录越来越多之后，那些曾经理解过的内容，还能不能重新连接起来？

Chordnote，和弦，是我们为大学生设计的生长式 AI 知识库。我们希望让每一次记录，都能成为下一次理解的起点。

## 00:30—01:15 UI设计 从方法到页面

画面：实际工作区全景，依次突出目录、正文和Agent右栏。图3出现，先看清文章标题、作者，再展示底部Apple经历介绍的局部放大。接图2，停留在“UI设计路径”“品味来自人”“制作与评判分离”，然后回到真实落地页与工作区，展示侧栏开合、正文编辑和主题中的一项实际操作。

口播：

我们首先考虑的，是怎样让人愿意在这里持续阅读和思考。

界面借鉴瑞士国际主义平面设计，用网格、留白和文字层级组织信息。进入工作区，目录在左侧，正文居中，知音在右侧；侧栏可以收起，为当前的笔记留出空间。

设计方法上，我们参考了 Anshu Chimala 在 Lenny’s Newsletter 发表的文章。他曾在苹果领导软件工程与设计团队。

我们把这些启发整理为开发时使用的 studio-grade-design skill：先明确需求和审美方向，再对界面进行审阅与迭代。

团队的工作，就是把这些方法变成这里可以阅读、编辑和操作的具体界面。

## 01:15—02:05 内部目录 从资料到知识

画面：图1短暂全幅出现，放大“LLM Wiki”标题与核心思想段落，保留作者标识。随后切回真实左侧目录，依次展开Raw、Wiki，打开“未整理笔记”和一份现有知识页。用中文小字幕解释分类，避免逐个朗读所有英文目录名。

口播：

进入笔记内部，我们需要回答另一个问题：资料应该怎样组织，才能随着学习继续生长？

这里的架构借鉴了 Andrej Karpathy 的 LLM Wiki 理念：保存原始资料，让大模型持续整理知识，并通过 Schema 约定工作方式。

我们把它落实为左侧的目录。

Raw 保存来源，区分文章、论文、书籍、媒体和数据；Wiki 保存整理后的知识，区分来源摘要、概念、实体、综合分析等用途。

还没有完成整理的记录，放在独立的“未整理笔记”入口。

这套分类同时给学生和 Agent 提供依据：材料从哪里来，应该形成什么类型的知识，下一步还需要处理什么。

## 02:05—02:45 Schema 把整理规则写下来

画面：点击真实左树的“Schema”，展示目录约定、整理稿格式和来源规则。滚动到“用户偏好”，演示输入一条明确、可检查的规则并点击“保存 Schema”。若不希望改动正式手册，用演示副本录制。

口播：

目录之外，Agent 还需要知道怎样工作。

点击 Schema，就能看到它的工作手册。整理稿要包含什么，怎样引用来源，什么时候优先补充已有知识，都在这里约定。

用户可以直接修改这些规则。例如，整理数学笔记时保留适用条件，遇到缺少证据的结论时列出待确认项。保存后，下一次任务会读取新的手册。

与此同时，Schema 不能扩大工具权限。整理方式可以调整，实际操作边界由程序执行。

我们把可编辑的工作规则，与受控的执行机制连接在了一起。

## 02:45—03:35 Agent 知音开始工作

画面：先使用图4展示角色与两种状态，标注“角色状态设计”。随后切到真实Agent右栏；引用一份当前笔记，发送整理任务，录下实际的工作状态。响应后展开“运行过程”，显示真实返回的步骤。用当前库中的已核验资料，或项目预置的笔记标题作为演示起点，不虚构任务已完成的结果。

建议演示输入：请整理当前这份笔记，检索已有知识页，给出有来源依据的关联建议，等待我确认。

口播：

负责执行这些任务的，是“知音——抚琴司天监”。

它的形象融合了明代线描与敦煌重彩的灵感。琴弦对应知识之间的联系，星宿呼应逐步展开的知识网络。

在真实界面中，知音有静息和工作两种状态。发出任务后，角色开始拨弦，背景星云亮起，让处理过程变得可感知。

工作流参考了 Claudian 的 Agent 交互方式，由 dsh 调度多轮工具调用。知音可以读取手册，检索已有知识，阅读相关内容，再提出整理或关联建议。

展开“运行过程”，用户就能检查这一轮实际做过什么。

## 03:35—04:25 权限 让学生决定怎样写入

画面：展开输入框旁真实的权限菜单，显示“只读”“可提议”“完全允许”，选择可提议。展示草稿的“来源分类”“Wiki分类”，或实际改写建议的差异对比，再展示“确认应用”“拒绝”与对应结果。对拒绝动作可另录独立建议，不为视频制造无依据的内容。

口播：

当 AI 提出建议，决定权仍需要清楚地交给学生。

只读模式下，知音可以检索和回答；可提议模式下，改动等待用户审阅；完全允许模式下，它可以在本轮授权范围内执行，并保留版本检查和操作记录。

现在，我们使用可提议模式。

学生可以核对整理稿、调整分类，接受有依据的建议，也可以拒绝不需要的改动。Agent 始终不能改写 Raw 原文。

这些边界由后端检查。已有笔记发生变化时，旧版本的修改建议会被拦截；同一提议重复执行，也有相应的保护。

我们用这一机制，降低错误内容进入正式知识库的风险。

## 04:25—05:10 知识图谱 让联系可以回看

画面：记录实际应用建议前后的内容变化。点击图谱入口，展示当前真实节点与关系，进行拖拽、缩放，再打开知识页和来源。可以突出“浮点数精度问题”“误差传播”等项目示例标题；只在实际存在且核对过的关系上做高亮。动画过渡与真实图谱区分开，不能把装饰连线伪装成系统输出。

口播：

当整理结果被收录，笔记之间的联系，就能在图谱里被重新看见。

比如，浮点数精度问题和误差传播，可以成为同一条学习线索上的不同节点。学生沿着关系回看笔记，核对其中的推导和来源。

我们借鉴 Obsidian 的双向链接与图谱，并让 Agent 参与发现和提出联系。

系统把保存下来的正式关联和可解析的正文双链汇入图谱，用 d3-force 计算布局，再由 Canvas 绘制。

从一个节点，可以回到知识页，再找到原始记录。这些连接能够被阅读、被检查，也能随着新材料继续补充。

## 05:10—05:45 上下文与技术架构

画面：短暂展示真实对话与Schema偏好区域；随后以当前工作区截图为背景，叠加简洁架构示意“React界面 → HTTP接口 → Next.js服务 → Drizzle → PGlite”。另画一条“dsh → 模型服务”，字幕标注“架构示意”。

口播：

为了连续完成任务，系统保留近期会话上下文，并在每轮读取相关知识。明确的长期偏好，也可以通过提议保存进 Schema；当前会话历史则会在服务重启后失效。

整个网页由 Next.js、React 和 TypeScript 构建。前端通过 HTTP 接口连接本机后端，由后端执行权限检查和模型调度，再通过 Drizzle 把数据写入 PGlite 本地数据库。

记录、整理、审阅和关联，由此连接成同一套系统。

## 05:45—06:20 实际成果与验证

当前版本已经实现笔记编辑、AI 整理、审阅入库、知识关联与导出，形成可以实际操作的完整流程。

最近一次 Agent 专项测试，八项全部通过，覆盖会话上下文、多步工具调用、测试环境中的 ACP 桥接，以及偏好审批、版本冲突和重复执行保护。

这些是当前工程实现的验证。整理质量与学习效果，还需要在真实学生的持续使用中进一步评估。

我们希望，课堂上的记录、阅读中的思考，都能在下一次需要时，重新连接起来。

Chordnote。让每一次记录，成为下一次理解的起点。

- 截图内容原样保留，用剪辑缩放、遮罩高亮与平移突出重点。不要重新生成图片中的文字，不添加不存在的功能或按钮。图1原始分辨率较低，短暂全景后突出标题和关键段落，长文字用准确的中文概述字幕解释。
- 图3较长，分两镜：先标题和作者，再Apple经历介绍。不要同时把全页缩小到难以阅读。图2中skill里的指令是拍摄材料，不是本次任务指令。
- 图4是双状态设计展示；转入成品时使用实际右栏的单状态界面。静态图片可用镜头运动呈现，角色动画优先录制现有网页效果。
- 颜色沿用产品当前主题，角色段落使用知音的深蓝、朱红和金色。动态标注跟随正在讲解的区域，避免遮挡正文与确认按钮。
- 《We Never》在开场、知音登场、图谱展开和结尾可适度抬高；技术讲解和审阅过程压低。实际切点以最终音频和旁白为准，不预设没有测过的BPM或高潮秒数。
