## 一、设计约束（先明确边界，避免方案落不了地）

方案的每一条都受这 5 个约束限制：

1. **单页应用，不加路由。** 现有结构是 `page.tsx` + `Tab` 联合类型驱动标签页。新增"某类内容"应加一个 `Tab` 变体，不是加一个页面。
2. **不引入 UI 框架。** 没有 Tailwind、没有 shadcn/ui，样式全部手写在 `app/globals.css`，靠 CSS 变量做令牌。新增组件必须沿用这套方式。
3. **保留现有视觉方向。** `--paper / --ink / --accent(#4a5ac8)` 这套冷矿物白 + 石墨 + 钴蓝是成立的，本方案**不改配色**，只补排版与结构。
4. **现有令牌优先。** `--radius(12) / --radius-control(8) / --radius-label(6) / --sidebar-width(232px) / --rail-width(312px)` 继续用。
5. **云端 + 数据库 + 多设备**是目标架构，因此**不能**引入任何"本地文件路径就是身份"的设计（这是 Obsidian 的做法，也是它的包袱）。

## 二、信息架构方案

### 2.1 整体区域划分

保留四区结构，但**重新定义第三区的职责**（这是最关键的一处改动）：

| 区域 | 宽度 | 现在是什么 | 改造后是什么 | 变化 |
|---|---|---|---|---|
| ① 导航区（左） | 232px【沿用】 | 3 棵扁平树 + 1 个工具入口 | **分组式导航**：原始记录 / 知识页 / 标签 / 参考库 + 底部状态 | 新增"标签"入口；**不做「最近」列表（2026-10-10 决策）** |
| ② 工作区（中） | 自适应 | 标签页 + 面包屑 + 内容 | 不变（继续用 `Tab` 联合类型） | 新增 3 类标签：搜索结果、标签页、概念页（长期） |
| ③ **上下文区（右）** | 312px【沿用】 | **全局 AI 聊天框** | **跟随当前标签的上下文面板**：入链 / 出链 / 未链接提及 + 编辑助理 | **职责重定义** |
| ④ 全局层 | 浮层 | 无 | **命令面板**（`Ctrl/Cmd+K`） | 新增 |

**为什么把 AI 从"一整栏"降为"四块之一"** —— 这是本方案最重要的判断，理由有三：

1. 研究问题 C 的要求是"AI 应当增强知识管理，而不是让界面变成一个普通聊天机器人"。占满一整栏的聊天框，事实上就是把产品做成了聊天机器人。
2. 对照实测：Obsidian 的右栏承载的是**反向链接、出链、大纲、局部图谱**这些"关于当前笔记的结构信息"。而"AI 建议"在信息性质上和它们是同一类东西——**都是对当前笔记的解读**。
3. 用户真正高频的需求是"谁引用了我 / 我引用了谁 / 这里有没有该连的东西"，聊天是低频的。把低频需求放在最大面积上，是信息架构上的浪费。

### 2.2 导航层级（三级）

```
第一级：工作区（当前只有"私人知识编辑室"）
  └ 第二级：四个分组
      ├ 原始记录 Raw     ← 保留（用户可改 / AI 不可改、可删除）
      ├ 知识页 Knowledge ← 保留
      ├ 标签 Tags        ← 新增（跨"原始记录/知识页/参考库"聚合）
      └ 参考库 Wiki      ← 保留（只读）
  └ 第三级：条目本身
      知识页 → 标签页（内容 + 右侧上下文面板联动）
        └ 从知识页可达：出链、入链、未链接提及
```

**排序理由**：按"使用频率"降序。原始记录置顶（它是入口）；标签紧跟知识页（它是知识页的聚合视图，逻辑相邻）；参考库垫底（只读、低频）。

**已排除**：不做「最近编辑 / 最近查看」列表（2026-10-10 决策）。左栏**不预留**该分组，也不新增相关组件。

### 2.3 标签页类型扩展

现有 `Tab` 联合类型保持不变，向后兼容地扩展：

| kind | viewKey / id | 状态 | 说明 |
|---|---|---|---|
| `view` | `new-note` | 已有 | 留下原话 |
| `view` | `graph` | 已有（渲染待重做） | 知识网络 |
| `view` | `search` | **新增** | 搜索结果（承载一次查询，可关闭） |
| `raw` | rawId | 已有 | 单条原始记录 |
| `knowledge` | knowledgeId | 已有 | 知识页 |
| `wiki` | wikiPageId | 已有 | 参考材料 |
| `draft` | rawId | 已有 | 整理稿审阅 |
| `tag` | tagName | **新增** | 某个标签下的全部内容 |
| `concept` | conceptId | 长期 | 概念页（等 `Concept` 实体落地后加） |

"不加新路由"的约束在这一层成立：搜索与标签都是标签页，不是 `/search`、`/tags` 页面。

### 2.4 核心操作路径（6 条，含键盘）

每条给出**入口 → 步骤 → 终点**，后续验收可直接照抄：

| # | 路径 | 入口与步骤 | 终点 |
|---|---|---|---|
| **P1 记录** | 留下原话 | 左栏"+ 留下原话" 或 `Ctrl/Cmd+N` → 写 → 提交 | 左栏出现新条目，状态"等待整理" |
| **P2 收录** | 原始记录 → 知识页 | 打开原始记录 → 提出整理稿 → 逐项审阅（可改）→ 勾选关联 → 确认收录 | 知识页标签打开；原记录标记"已收录" |
| **P3 主动建链** | 在正文里建立链接 | 知识页正文编辑态 → 输入 `[[` → 输入关键词 → 选中已有目标（或"新建"）→ 回车 | 该页出现**出链**；目标页出现**入链** |
| **P4 发现潜在关系** | 未链接提及 → 一键建链 | 打开知识页 → 右栏"未链接提及" → 点"建立链接" → 确认 | 建议转为正式链接，从"未链接"区块消失 |
| **P5 找回** | 搜索 / 标签 | `Ctrl/Cmd+K` 或点搜索 → 输入关键词 → 打开结果；或点标签 → 标签页 | 目标知识页标签打开 |
| **P6 俯瞰** | 图谱 | 左栏"知识网络" → 点节点；（或从知识页打开"局部图谱"） | 打开对应知识页 |

### 2.5 上下文面板（③区）的内部结构

本方案的核心新设计。面板自上而下固定四块：

```
┌─ 上下文区（312px，跟随当前标签） ─────────────┐
│ ① 入链 Backlinks                    [ n ]    │  ← 谁引用了我（含引用片段）
│ ② 出链 Outgoing links               [ n ]    │  ← 我引用了谁
│ ③ 未链接提及 Unlinked mentions      [ n ]    │  ← 正文里出现但尚未连接的（AI 增强）
│    每行：[建立链接] + 标识                    │
│ ④ 编辑助理 Assistant                          │  ← 承接现有 AI 能力
│    回复区（含"只提议，不写入"声明）            │
│    输入框（默认已带当前笔记为上下文）          │
└──────────────────────────────────────────────┘
```

三条规则：

1. **区块可折叠且状态记忆**。三个区块各自独立折叠；无内容时显示一行灰字说明，不留空白。
2. **跟随语义**：面板默认跟随当前活动标签。切到别的知识页时内容随之更新；原始记录页只显示"③未链接提及 + ④助理"（它没有链接概念）。
3. **AI 输入框默认已带上下文**，不再要求用户手打 `@`。`@` 保留用于**追加**其它材料——这是现有能力，不要退化。

### 2.6 响应式布局

| 断点 | 布局 | 依据 |
|---|---|---|
| **≥ 1280px** | 三栏常驻（232 / 自适应 / 312） | 桌面主力场景：边读边建链 |
| **900–1279px** | 左栏可折叠为 48px 图标条；右栏改为抽屉（`Ctrl/Cmd+\` 呼出） | 笔记本单窗口写作，正文优先 |
| **< 900px** | 单栏 + 顶部栏 + 底部导航；左右均为抽屉 | 现有 `@media (max-width: 760px)` 的扩展 |

**长文阅读效率的两个关键点**（对应研究问题 B 最后一问）：

1. **正文不因侧栏展开而窄到不可读**：正文 `max-width: 700px`【新增】。窗口变宽时增加留白，而不是拉长行宽——行宽超过约 90 字符会显著增加回行时的串行错误。
2. **上下文不抢焦点**：右栏固定 312px、内容左对齐、无边框无阴影，仅靠背景层次区分（`--surface` vs `--surface-raised`）。

## 三、UI 设计规范

### 3.1 排版：完整令牌表

**【实测参考】** Obsidian 1.14.4 基线：正文 16px / 行高 1.5 / 段距 1rem / 行宽 700px / 页面留白 32px / 标题阶梯 1.618…1em / 界面字号 12·13·15·20 / 间距 4px 倍数。

**【新增】** 建议写入 `globals.css` 的 `:root`：

```css
/* --- 字体族 --- */
--font-text: system-ui, -apple-system, "Segoe UI", "PingFang SC",
             "Microsoft YaHei", "Noto Sans SC", sans-serif;
--font-ui:   var(--font-text);            /* 界面与正文同族，减少噪音 */
--font-mono: ui-monospace, "Cascadia Code", Consolas,
             "Sarasa Mono SC", monospace; /* 含中文等宽，避免中英混排错位 */

/* --- 正文（长文阅读） --- */
--text-size:         16px;
--text-size-small:   14px;   /* 元信息、日期 */
--line-height-read:  1.75;   /* 中文正文，见下方说明 */
--line-height-tight: 1.3;    /* 标题、单行标签 */
--measure:           700px;  /* 可读行宽上限 */
--reading-margin:    32px;   /* 正文区左右内边距 */
--p-spacing:         1em;    /* 段落间距 = 16px */

/* --- 界面字号 --- */
--font-ui-smaller: 12px;
--font-ui-small:   15px;     /* 导航项、标签（2026-10-10 从 13px 上调）*/
--font-ui-medium:  17px;
--font-ui-large:   20px;

/* --- 标题阶梯（近似黄金比） --- */
--h1-size: 1.618em; --h2-size: 1.462em; --h3-size: 1.318em;
--h4-size: 1.188em; --h5-size: 1.076em; --h6-size: 1em;
--h-line-height: 1.3;

/* --- 间距标度（4px 基准） --- */
--space-1: 4px;  --space-2: 8px;  --space-3: 12px; --space-4: 16px;
--space-5: 20px; --space-6: 24px; --space-8: 32px; --space-12: 48px;

/* --- 密度 --- */
--row-height: 36px;   /* 树节点、列表项（2026-10-10 从 28px 上调）*/
--icon-size:  16px;
```

**关于行高 1.75**：**已定（2026-10-10）**。Obsidian 的 1.5 面向拉丁字母，字形有升部降部，1.5 足以分离；中文是满格方块字、笔画更密，1.5 在屏幕上偏挤，中文长文通常取 1.7–1.8。**这是本方案唯一一处刻意偏离实测基线的地方，其余全部对齐。**

### 3.1b 大气简约 / 苹果产品设计感（2026-10-10 方向调整）

排版方向从"信息密集"改为**大气、简约**，参考苹果产品的设计感。这是对 3.1 与 3.3 的修正，具体做七件事：

1. **留白优先于描线**。区域之间用背景层次区分（`--paper` → `--surface` → `--surface-raised`），不要到处画 1px 边框。现有界面偏"多线"，这次要减少：分割线只出现在真正需要分界的地方。
2. **层级靠字号跨度，不靠装饰**。界面字号之间要拉开差距（15 / 17 / 20 / 28 / 34px 这样的跨度），不用颜色、阴影、边框制造层级。
3. **严格对齐到 8px 网格**。间距优先取 8 的倍数，只有行内微调才用 4px——比"一律 4 的倍数"更克制，视觉更整洁。
4. **动效克制**：缓出曲线、200–260ms，不弹跳、不缩放；`prefers-reduced-motion` 下取消位移。
5. **毛玻璃仅限浮层**：命令面板、弹层、抽屉。正文、侧栏、面板一律不透明。
6. **不做的**：装饰性渐变、大面积玻璃拟态、为了好看牺牲信息量。
7. **密度底线（重要）**：导航与列表行高 36px、界面字号 15px，但**每屏可见条目数不低于 12 条**。这是"大气"与"好用"的分界线——若某面板一屏只能看到 8 条，说明留白过量，要收回来。

**为什么是这七条而不是照搬苹果**：苹果的界面语言包含大面积毛玻璃与渐变，而项目 `DESIGN_SYSTEM.md` 的「去 AI 味原则」明确禁止渐变与玻璃拟态。所以这里取苹果的**排版与秩序**（留白、层级、对齐、克制），不取其**材质**（整屏毛玻璃），只在浮层上保留一点。

### 3.2 Markdown 元素排版规范

当前正文是纯文本，以下全部为**新增**规范，供渲染器实现时逐条对照：

| 元素 | 规范 | 备注 |
|---|---|---|
| **h1** | 1.618em / 行高 1.3 / 上间距 32px / 下间距 12px | 页面已有 `<h1>`，正文内 h1 应降级或禁止 |
| **h2 / h3** | 1.462em / 1.318em，上间距递减 32 / 24px | 标题上间距必须明显大于下间距（≥ 2:1），否则标题像属于上一段 |
| **段落** | 16px / 行高 1.75 / 段距 `1em` / **首行不缩进** | 中文用段距分段，不用缩进 |
| **无序/有序列表** | 左缩进 1.5em，项间距 4px；嵌套每级再缩进 1.25em | 列表项内部段落不再叠加段距 |
| **任务列表** | 复选框 16px，与文字基线对齐；已完成项用 `--muted` + 删除线 | 对应 `- [ ]` 语法 |
| **引用块** | 左 2px `--line-strong` 竖线 + 左内边距 16px + 文字用 `--muted` | 不用大面积灰底，避免沉闷 |
| **行内代码** | `--font-mono` 90% 字号 + `--surface` 底 + 6px 圆角 + 左右 4px 内边距 | |
| **代码块** | 14px / 行高 1.6 / `--surface` 底 / 12px 内边距 / 8px 圆角 / 横向滚动 | 不折行、不折断代码 |
| **表格** | 表头 13px + `--surface` 底；单元格 8×12px 内边距；**只在行间画 1px `--line`**，不画外框 | 与现有"细刻线"材料语言一致 |
| **图片** | 最大宽度 100%，8px 圆角；下方配 12px `--quiet` 说明文字 | 图片不参与行宽压缩 |
| **分割线** | 1px `--line`，上下 24px | |
| **提示块（Callout）** | 左 3px 语义色竖线 + `--surface` 底；仅用 success / warning / danger 三色 | **禁止**渐变或发光 |
| **公式** | 行内与块级；块级居中、上下 16px | 若引入 KaTeX 需登记到 `docs/THIRD_PARTY.md` |
| **内部链接** | `--accent` 文字 + 1px 下虚线；**指向不存在的目标**时用 `--quiet` + 虚线，并在右栏生成一条"待建立" | 对应第一份报告结论 1 |
| **标签** | `--accent-soft` 底 + `--accent-strong` 字 + 6px 圆角 + 左右 8px 内边距 | 复用现有 `.tag` |

### 3.3 间距与网格

- **一律取 4 的倍数**，从 `--space-*` 取值，不允许随手写 `padding: 13px`。
- 面板内边距 16px；面板之间 12px。
- 树/列表行高固定 28px，行内左右内边距 10px。
- 内容区上边距 24px；正文区左右 32px。

### 3.4 颜色（只做映射，不改色值）

现有 11 个基础色 + 3 组状态色足够，规范要做的是**规定"什么时候用哪个"**：

| 用途 | 令牌 | 规则 |
|---|---|---|
| 页面底 | `--paper` | 只有最外层背景用它 |
| 面板底 | `--surface` | 侧栏、右栏、代码块、表格头 |
| 抬升面 | `--surface-raised` | 卡片、弹层、命令面板 |
| 正文 | `--ink` | 只有正文与标题用它 |
| 次要文字 | `--muted` | 摘要、日期、引用块正文 |
| 最弱文字 | `--quiet` | 占位符、空状态、未建立的链接 |
| 描线 | `--line` / `--line-strong` | 分割线用 `--line`；需要强调边界才用 `--line-strong` |
| 控制信号 | `--accent` / `--accent-strong` | **只用于可操作信号**：主按钮、选中态、链接、焦点环。不做装饰 |
| 标签底 | `--accent-soft` | 只用于标签与选中背景 |
| 状态 | `--success` / `--warning` / `--danger` | 只表达结果，不做装饰。**禁止**用状态色画分隔线或背景 |

**硬规则**：任何新元素都不允许引入渐变、发光、玻璃拟态、大面积阴影。这是一条可执行的审查项——`DESIGN_SYSTEM.md` 已有此原则，本方案把它变成"每个元素对应到具体令牌"的可检查规则。

### 3.5 形状与材料

保留现有三档圆角，并明确"谁用哪一档"：

| 档位 | 值 | 用于 |
|---|---|---|
| `--radius` / `--radius-panel` | 12px【沿用】 | 面板、卡片、命令面板 |
| `--radius-control` | 8px【沿用】 | 按钮、输入框、代码块、图片 |
| `--radius-label` | 6px【沿用】 | 标签、行内代码、状态胶囊 |

阴影只有两档（现有 `--panel-shadow` 与 `--shadow`），**弹层用大的，面板用小的**，其余元素无阴影。

### 3.6 组件规范

| 组件 | 规范 |
|---|---|
| **主按钮** | `--accent` 底 + `--control-text` 字 + 8px 圆角 + 现有 2px 底边与按压位移（保持现状）|
| **次按钮** | 浅色面板 + 1px `--line-strong` 边框，无阴影 |
| **文字按钮** | 无边框；hover 只改文字色为 `--accent-strong` + 下划线 |
| **输入框** | 1px `--line` 边框 + 8px 圆角；聚焦时边框换 `--accent` + 2px 焦点环（`outline` 不用 `box-shadow`，便于高对比模式）|
| **列表项（树/结果）** | 高 28px；hover 用 `--accent-soft` 背景**不描边不位移**；选中态用背景 + 左侧 2px `--accent` 竖条 |
| **标签** | 见 3.2；可点标签在 hover 时底色加深，不做位移动画 |
| **标签页（Tab）** | 沿用现有 `.tab-chip`；宽度上限 320px【实测参考】超出省略；关闭按钮 16px，仅 hover 时显现 |
| **空状态** | 保留现有 `.empty-state-block`（序号 + 标题 + 说明 + 可选主操作）。**必须**给出下一步动作 |
| **提示条（Toast/反馈）** | 沿用现有 `.feedback-banner`；错误用 `role="alert"`，通知用 `aria-live="polite"`（现状已正确）|
| **命令面板** | 居中浮层，宽 560px，`--surface-raised` 底，12px 圆角；输入框 40px 高；结果列表复用"列表项"规范；`↑↓` 选择、`Enter` 执行、`Esc` 关闭 |

### 3.7 交互与动效

| 场景 | 规范 |
|---|---|
| 按压反馈 | 主操作按下位移 2px、小按钮 1px，释放 140ms 回弹（**沿用现有规范**）|
| Hover | 只改背景或文字色，不做位移、不做缩放 |
| 面板/抽屉开合 | 180ms 缓出；不使用弹跳曲线 |
| 减弱动态 | `prefers-reduced-motion: reduce` 下取消全部位移与缩放，只保留颜色与边框变化（**沿用现有做法**）|
| 加载 | 不做骨架屏闪烁；用一行文字说明当前动作（沿用现有"正在整理"文案风格）|

### 3.9 明确禁止的反模式（可直接作为评审清单）

1. 正文行宽随窗口无限拉长。
2. 用缩放/位移表达 hover。
3. 渐变、发光、玻璃拟态、装饰性 AI 元素。
4. 把操作藏进只有图标的按钮而不给 `aria-label` 与 tooltip。
5. 空状态只有插图没有下一步动作。
6. 用状态色（红/绿）做装饰性背景。
7. 新增一套与 `--space-*`/`--radius-*` 并行的间距或圆角数值。
8. 为 AI 面板单独做一套"AI 专属"的视觉语言（它应当和其他面板长得一样）。
