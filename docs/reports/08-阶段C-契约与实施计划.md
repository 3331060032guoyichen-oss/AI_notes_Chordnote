## 一、HTTP API 契约草案

### 1.1 路径命名策略

**【暂定决策】** 表名统一为 `raw_notes` / `notes`，但**接口路径保持现状**（`/api/raw`、`/api/knowledge`），只**新增**两组路径：

1. `/api/notes/*` —— 作为 `knowledge` 的**契约别名**，内部分发到同一服务函数。新增它是为了给外部 Agent 一份命名一致的契约（`note_ai_metadata.note_id` 指向 `notes`，路径也叫 `notes` 才不绕）。
2. `/api/proposals/*`、`/api/links/*`、`/api/search`、`/api/tags/*`、`/api/audit`。

**理由**：避免一次性重命名导致前端大改（降低 Phase D 风险），同时不让外部契约背着历史命名。若要**彻底统一**（连旧路径一起改），请在未决问题里确认。

### 1.2 读取类

| 方法与路径 | 用途 | 主体 | 权限 | 备注 |
|---|---|---|---|---|
| `GET /api/search?q=&tag=&sort=&limit=&cursor=` | 搜索笔记 | 全部 | 只读，需归属检查 | 分页用游标 |
| `GET /api/notes?limit=&cursor=&sort=` | 笔记列表 | 全部 | 只读 | 默认 `updated_at desc` |
| `GET /api/notes/:id` | 单篇笔记 | 全部 | 只读 | |
| `GET /api/notes/:id/backlinks` | 入链（谁引用了我）| 全部 | 只读 | 复用现有 backlinks 逻辑 |
| `GET /api/notes/:id/links` | 出链（我引用了谁）| 全部 | 只读 | 新增 |
| `GET /api/notes/:id/ai-metadata` | AI 元数据 | 全部 | 只读 | |
| `GET /api/tags` | 标签与计数 | 全部 | 只读 | |
| `GET /api/tags/:name` | 某标签下的笔记 | 全部 | 只读 | |
| `GET /api/raw` `/api/raw/:id` | 原始记录 | 全部 | 只读 | 保留 |
| `GET /api/graph` | 图谱数据 | 全部 | 只读 | 保留 |

### 1.3 写入类 —— 白名单（Agent 可自动执行）

| 方法与路径 | 用途 | 允许主体 | 幂等 | 事务 |
|---|---|---|---|---|
| `POST /api/notes` | 创建笔记 | 用户 + **Agent（白名单）** | **需 `Idempotency-Key`** | T1 |
| `POST /api/notes/:id/tags` | 补充标签（**仅新增**）| 用户 + **Agent（白名单）** | 建议带 | T5 |
| `PATCH /api/notes/:id/ai-metadata` | 更新 AI 元数据 | 用户 + **Agent（白名单）** | 建议带 | T6 |
| `POST /api/raw` | 创建原始记录 | 用户 | 建议带 | 单语句 |

**服务端必须强制（对应项目文档第六章的字段白名单）**：

- `POST /api/notes` 不得指定已存在的 `id`；不得覆盖任何已有笔记；服务端限制标题/正文长度与创建频率。
- `POST /api/notes/:id/tags` **只接受新增**；请求中若包含删除或重命名语义 → `403 FORBIDDEN_OPERATION`。
- `PATCH /api/notes/:id/ai-metadata` 只允许写 `note_ai_metadata` 的字段；**请求体里出现正文类字段一律拒绝**。

### 1.4 写入类 —— 用户直接编辑

| 方法与路径 | 用途 | 允许主体 | 版本检查 |
|---|---|---|---|
| `PATCH /api/raw/:id` | 用户修改原始记录 | **仅用户**（AI 调用 → 403）| 需 `version` |
| `PATCH /api/notes/:id` | 用户修改笔记正文/标题 | **仅用户**（Agent 调用 → 403，须走提议）| 需 `version` |
| `DELETE /api/raw/:id` | 删除原始记录 | 仅用户 | — |

**【暂定决策】** 这三条是 5.3 节"按主体分流"的落地：**Agent 打这些接口会被服务端拒绝并提示改用提议**，而不是靠提示词约定。

**【已确认决策】**（2026-10-10）这三条属于 **`user_edit`** 类：**允许主体仅 `user`**。Agent 主体调用必须被服务端拒绝（`403 USE_PROPOSAL_FLOW`）**并提示改用哪个提议工具**——不允许靠提示词约定，也不允许前端代为判断。

### 1.6 三类操作与接口的映射（正式约束落地）

> **【已确认决策】** 服务端按**操作主体**分流；不允许前端代替判断，也不允许 Agent 通过调用用户接口绕过提议机制。主体身份来自服务端凭据 / 会话上下文，**不来自请求参数**。

| 接口 | 类 | `user` 主体 | `agent` 主体 |
|---|---|---|---|
| `GET /api/search`、`GET /api/notes*`、`GET /api/tags*`、`GET /api/raw*`、`GET /api/graph` | 只读 | 允许 | 允许 |
| `PATCH /api/notes/:id`、`PATCH /api/raw/:id` | **`user_edit`** | 允许（走版本检查）| **403 `USE_PROPOSAL_FLOW`** |
| `POST /api/raw` | `user_edit` | 允许 | 拒绝（Agent 应改用 `POST /api/notes`）|
| `DELETE /api/raw/:id` | `user_edit`（高风险）| 允许（显式确认）| 拒绝 |
| `POST /api/notes` | **`agent_auto_write`** | 允许 | 允许（需幂等键）|
| `POST /api/notes/:id/tags` | **`agent_auto_write`** | 允许 | 允许（**仅新增**）|
| `PATCH /api/notes/:id/ai-metadata` | **`agent_auto_write`** | 允许 | 允许 |
| `POST /api/links`、`DELETE /api/links/:id` | **`agent_proposal`** | 允许（直接执行，走事务 T4）| **只生成提议，不直接写入** |
| `POST /api/proposals` | `agent_proposal` | 允许 | 允许 |
| `POST /api/proposals/:id/approve` / `reject` | 审核 | 允许 | **拒绝**（Agent 不能替用户批准）|
| `POST /api/proposals/:id/apply` | `agent_proposal` 执行 | 允许 | 允许（须已批准 + 幂等键）|
| `GET /api/audit` | 只读（受限）| 允许 | **拒绝** |

**两条值得注意的分界**：① **批准/拒绝提议只有用户能做**——否则"提议"就失去了审核意义；② **审计记录不对 Agent 开放**。

### 1.5 提议与关系

| 方法与路径 | 用途 | 说明 |
|---|---|---|
| `POST /api/proposals` | 提交提议 | 需 `kind`、`payload`、`base_version`；Agent 与用户都可提交 |
| `GET /api/proposals?status=&limit=&cursor=` | 提议列表 | 默认只看 `pending` |
| `GET /api/proposals/:id` | 提议详情（含 diff）| |
| `POST /api/proposals/:id/approve` | 批准 | 仅用户/已授权主体；写审计 |
| `POST /api/proposals/:id/reject` | 拒绝 | 写审计 |
| `POST /api/proposals/:id/apply` | 执行 | **需已批准 + `Idempotency-Key`**；执行前重新校验权限与版本；事务 T3/T4 |
| `POST /api/links` | 建立正式关系 | **用户 → 直接执行（T4）；Agent → 生成 `link_create` 提议** |
| `DELETE /api/links/:id` | 删除正式关系 | 同上（`link_delete`）|
| `GET /api/audit?limit=&cursor=` | 审计查询 | 【暂定决策】仅暴露给用户主体，不暴露给 Agent |

**【暂定决策】** `POST /api/links` 与 `DELETE /api/links/:id` 对 Agent 返回"已创建提议"而非直接写入——**同一个路径按主体分流**，避免 Agent 需要知道"该调哪个接口"。

## 二、通用约定（分页、幂等、版本、错误）

### 2.1 分页

**【暂定决策】** 一律**游标分页**（不用 `offset`），默认 `limit=20`、上限 `100`；响应带 `next_cursor`。理由：offset 在并发写入时会漂移、重复或漏项。

### 2.2 排序

**【暂定决策】** 默认 `updated_at desc`；可用 `sort=created_at|updated_at|title`，倒序用 `-` 前缀。

### 2.3 幂等

**【暂定决策】**

- 需要幂等的写操作：`POST /api/notes`、`POST /api/proposals/:id/apply`、`POST /api/links`。
- 机制：请求头 `Idempotency-Key`，落 `idempotency_keys` 表（唯一键 `(user_id, key)`）。
- 重复请求返回**第一次的响应**，不重复产生副作用。
- **不为只读请求加幂等键**（项目文档明确说不需要）。

### 2.4 版本冲突

**【暂定决策】**

- 请求携带当前版本（`If-Match` 头或 body 的 `version`）。
- 条件更新命中 0 行 → `409 VERSION_CONFLICT`。
- 提议执行时冲突 → 提议转 `stale` + `409 PROPOSAL_STALE`，并提示重新读取生成新提议。

### 2.5 错误语义

保持你项目现有格式 `{ error: { code, message } }`（这是好资产，不要推翻），**新增错误码**：

| HTTP | code | 含义 |
|---|---|---|
| 400 | `VALIDATION_ERROR` | 参数/字段校验失败 |
| 401 | `UNAUTHORIZED` | 未提供或凭据无效 |
| 403 | `FORBIDDEN_RESOURCE` | 资源不属于当前主体 |
| 403 | `FORBIDDEN_OPERATION` | **操作不在白名单内**（提示改用提议）|
| 403 | `USE_PROPOSAL_FLOW` | **Agent 调用了 `user_edit` 类接口**；响应须指明应改用哪个提议工具 |
| 404 | `NOT_FOUND` | 资源不存在 |
| 409 | `VERSION_CONFLICT` | 版本不匹配 |
| 409 | `PROPOSAL_STALE` | 提议依据的版本已过期 |
| 409 | `PROPOSAL_INVALID_TRANSITION` | 非法状态转换 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同一幂等键但请求体不同 |
| 429 | `RATE_LIMITED` | 限流 |
| 502/504 | `UPSTREAM_ERROR` / `TIMEOUT` | AI 上游异常（沿用现有语义）|

**【暂定决策】** 错误响应**不暴露**数据库错误原文、连接串、内部堆栈（项目文档第五章第 2、3 条明确要求）。服务端日志可记详情，客户端只给可读文案 + code。

## 四、`schema.md` 章节结构

**【暂定决策】** 采用项目文档第十章给定的 12 章结构，语言规范为**英文契约 + 中文注解**：

```
schema.md
 0. 语言与标注约定（英文契约 / 中文注解 / 三种状态标签）
 1. Scope and Architecture
      - 分层职责、调用路径、谁不信任谁
      [中文注解] 为什么 MCP 不得直连数据库
 2. Data Model
      - 表、字段、类型、主键/外键/索引、约束名
      [中文注解] raw_notes 与 notes 为何保留两层
 3. Ownership and Authorization
      - user_id 语义、主体类型、授权入口函数、演示期隐式单用户
 4. AI Metadata
      - note_ai_metadata 字段、可写字段白名单、source_version 语义
 5. HTTP API Contract
      - 路径、方法、参数、响应、错误码、分页、幂等、版本冲突
 6. MCP Tool Contract
      - 工具表（含"是否自动执行"列）、参数与错误、幂等行为
 7. Automatic Execution Policy
      - 白名单（字段级）+ 必须提议清单 + 高风险清单 + 按主体分流表
 8. Change Proposals and Approval
      - 状态机、合法转换、执行前校验顺序
 9. Versioning and Idempotency
      - version 语义、条件更新、stale 判定、幂等键
10. Error Handling
      - 错误码表 + 不得泄露的信息

      - 审计字段、不得记录的内容、凭据管理
```

**【暂定决策】** `agent-tools.md` 也暂不单独拆出——工具契约作为 `schema.md` 第 6 章，避免复制同一份契约。

## 五、迁移、测试、部署与回滚计划

## 附录：本轮（Phase C 前）新增的已验证事实

全部来自 `neon.com/docs/*`，核实日期 **2026-10-10**：

| # | 事实 | 来源 |
|---|---|---|
| F1 | **Netlify Functions 应使用 `@neondatabase/serverless`**（HTTP 或 WebSocket），而不是 TCP 驱动 | `connect/choose-connection`、`connect/connection-pooling` |
| F2 | serverless 驱动的 **HTTP** 传输：单查询更快（约 3 次往返 vs TCP 约 8 次），但**只支持非交互式事务** | 同上 |
| F3 | serverless 驱动的 **WebSocket** 传输：支持**交互式事务**，且**兼容 `node-postgres` 的 `Pool`/`Client` API** | 同上 |
| F4 | 池化连接可承载**最多 10,000 个并发客户端连接**；直连受 `max_connections` 限制（**约 100–4000**，取决于计算规格）| 同上 |
| F5 | Scale to Zero：闲置 **5 分钟后挂起**，再次查询时**在几百毫秒内自动恢复**；**免费计划无法关闭该设置** | `introduction/scale-to-zero` |
| F6 | Neon 官方支持 **`pg_dump` / `pg_restore`** 备份，并**提供"每夜自动 `pg_dump` 到 S3 + 保留策略"的 GitHub Actions 两段式指南** | `postgres/backup-restore/backups` |
| F7 | 即时恢复（PITR）历史窗口官方表述为"**1 天到 30 天，取决于套餐**"——**与定价页免费计划的"6 小时 / 1 GB 数据变更"口径不一致** | `postgres/backup-restore/backups` vs `pricing` |
| F8 | Neon 文档站现在整体以 **Lakebase Postgres（from Databricks）** 的名义组织 | `docs/llms.txt` |

**【推断】** F8 提示供应商归属发生了变化，**属供应商风险评估项**：免费额度的长期稳定性存在不确定性，因此本文把"独立 `pg_dump` 备份"列为强约束（正是该约束 5）——只要备份与代码都用标准 PostgreSQL，换家成本就可控。
