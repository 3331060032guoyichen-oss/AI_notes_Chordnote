## 00:00—00:35 落地页与问题

画面：展示落地页的产品名称、视觉主体和进入工作区的入口。随后进入笔记列表。

口播：

各位评委老师好，我们的作品是 Chordnote，和弦，一款面向大学生的生长式 AI 知识库。

在学习中，我们会记录课堂内容、阅读资料和解题思路。但笔记越来越多之后，整理和建立联系往往跟不上积累的速度。比如，线性代数中的向量投影，与统计学习中的最小二乘，本来可以互相帮助理解，却可能被放在两个互不关联的文件夹里。

我们希望让 AI 帮助学生发现和整理这些联系，同时让学生保留对知识内容和组织方式的决定权。

## 00:35—01:20 创意来源与具体改造

画面：依次出现LLM Wiki、Obsidian、Claudian的名称和来源字幕；用三组短词呈现“持续整理”“双向链接”“多步工具调用”，随后回到产品。

口播：

我们的创意主要来自三个方向。

首先是 Andrej Karpathy 的 LLM Wiki 理念：保留原始资料，由大模型持续维护知识页，并通过 Schema 约定工作方式。我们沿用这一结构，为大学生笔记设计了具体的来源分类、页面类型和整理规则。

其次是 Obsidian 的双向链接与知识图谱。我们借鉴它连接笔记的方式，让 Agent 参与阅读资料、寻找关联和提出建议，减轻手工维护的负担。

第三是 Claudian 的 Agent 工作流。我们参考多步工具调用的交互方式，将检索、阅读、整理和审阅连接起来。

这些借鉴最终落在一个具体问题上：怎样让 AI 的整理过程可理解、可控制，并真正进入学生自己的知识体系。

## 01:20—01:55 前后端与数据架构

画面：显示架构图“React界面 → HTTP接口 → Next.js业务服务 → Drizzle → 本机PGlite”；在后端旁边补充“dsh → 模型服务”。再切回工作区。

口播：

技术上，Chordnote 使用 Next.js、React 和 TypeScript 构建，前端负责笔记编辑、图谱和 Agent 交互。

用户的操作通过 HTTP 接口发送到本机后端，由后端检查权限、执行任务，再返回结果。数据通过 Drizzle 写入本机的 PGlite 数据库，不需要额外部署数据库服务。

Agent 使用 DeepSeek Harness 调度多轮模型与工具调用，并通过我们定义的受控工具访问知识库。模型可以选择兼容 API，也可以通过 Ollama 接入本地模型。

## 01:55—02:55 原始笔记与Schema

画面：打开准备好的“向量投影”原始笔记，展示已保存状态。打开Schema，停留在Raw/Wiki分类、整理稿格式和来源要求。回到笔记，向Agent发送下方演示指令。

演示输入：请整理这份向量投影课堂笔记，查找它与知识库中最小二乘相关内容的联系。保留推导条件和来源，把需要我确认的内容列出来。

口播：

接下来，我们用一份向量投影的课堂笔记，演示完整过程。

新内容首先保存为 Raw，也就是原始记录。AI 整理失败不会让这份原文丢失，Agent 也不能改写它的正文。

左侧的 Schema 是 Agent 的工作手册。这里区分资料的来源类型，以及知识页的用途，并约定整理稿应该包含摘要、要点、来源和待确认内容。

收到任务后，系统会加载当前工作手册和相关上下文。Agent 可以检索已有知识，继续阅读相关页面，再提出整理和关联建议。

用户也可以直接修改手册中的整理规则和偏好，保存后供下一次任务使用。但修改手册不会扩大工具权限。这让知识整理方式可以个性化，同时保留明确的执行边界。

## 02:55—04:00 权限与审阅机制

画面：展示三档权限，保持“可提议”。展示实际返回的工作步骤、整理稿或改写Diff；拒绝一项不需要的建议，再确认另一项。仅使用实际生成且核验过的内容。

口播：

为了让学生决定 AI 能做到哪一步，我们设置了三档权限。

只读模式允许检索、阅读和回答；可提议模式允许生成草稿和修改建议，等待用户确认；完全允许模式则可以在本轮任务授权范围内直接执行，并保留版本检查与操作记录。

现在使用的是可提议模式。我们先检查整理内容是否准确、关联理由是否成立。对于不需要的建议，可以拒绝；对于保留的内容，再确认应用。

这些限制由后端执行。系统会检查工具是否属于本轮权限，原始记录的正文也有单独的保护。

对于已有知识页的修改，系统还会检查版本。如果笔记已经被用户更新，旧提议会被拦截，避免覆盖新内容；重复执行同一提议，也有相应的保护。

因此，审阅既是界面上的操作，也是实际的数据写入机制。

## 04:00—04:45 知识网络与来源追溯

画面：打开实际收录的知识页，展示来源链接和关联理由。切换图谱，拖动、缩放、打开对应节点，再返回原始资料。

口播：

整理结果收录后，我们可以从知识页查看来源，并沿着链接阅读相关内容。

在这个例子中，向量投影与最小二乘的联系，需要由两端材料中的推导和条件支持。我们希望学生能够核对这条关系为什么成立。

图谱将已经保存的正式关联和可解析的正文双链转成节点与连线。布局由 d3-force 计算，再通过 Canvas 绘制，支持拖动、缩放和打开笔记。

这样，学生可以从图谱进入知识页，再回到原始记录，沿着来源检查自己的理解。新的材料也可以继续补充已有知识，让这个网络逐步生长。

## 04:45—05:25 会话上下文与长期偏好

画面：展示同一任务的追问，以及Schema中的“用户偏好”区域。如演示偏好保存，使用“以后整理数学笔记，请保留适用条件”这一明确输入，并展示真实确认过程。

口播：

为了支持连续工作，我们还区分了会话上下文与长期偏好。

近期对话和工具调用帮助 Agent 接着完成当前任务；用户明确表达的长期偏好，例如整理数学笔记时保留适用条件，可以通过提议写入 Schema。之后的新任务会重新读取这些偏好和当前知识内容。

目前，对话上下文保存在运行进程中，服务重启后会失效。长期延续依靠保存下来的知识页、规则和偏好，而不是永久保留全部聊天记录。

视觉上，我们借鉴瑞士国际主义平面设计的网格和信息层级，并将设计规则整理成 studio-grade-design，辅助界面方案的探索与迭代。
