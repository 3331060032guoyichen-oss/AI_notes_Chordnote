## 五、Markdown 文件夹接入的技术约束

三种方案已评估，结论见 ADR-0006：浏览器 File System Access API 不适用（服务端的 Agent 与索引拿不到句柄）；下一阶段采用本机文件服务，把读写限制在用户确认过的根目录内，并校验路径穿越与符号链接；桌面容器作为备选。**当前未实现，不得对外宣称支持。** 迁移前 PGlite 仍是唯一权威。

## 六、主要风险

- **凭据**：`data/settings.json` 在 POSIX 上是 0600，**Windows 忽略该模式**；没有系统钥匙串，也没有静态加密。准确说法是"不出本机、不进 Git、不进响应与日志"。
- **并发**：PGlite 单写者；将来文件成为权威后，Obsidian 与应用会同时写文件，必须靠哈希比对与原子重命名处理，不能静默覆盖。
- **迁移**：导出、写入、校验、回滚四步缺一不可；校验项包括数量、正文哈希、链接两端存在。
- **Prompt Injection**：现有系统提示词把材料声明为数据，工具层不提供写路径；新增 provider 不得绕过工具授权表。
- **其他写接口**未加本机来源检查，本次只收紧了设置接口。
